# v3.7.5 — 模糊删除路由优先级修复

**日期**：2026-07-13  
**类型**：缺陷修复 (bugfix)  
**影响范围**：`00_核心主体/脑.py` — `_ROUTE_PROMPT_V2` + 降级关键词匹配

## 问题描述

v3.7.4 新增的 `ask_clarify` 澄清流程存在路由优先级缺陷：当用户说"删除之前的财务数据"时，路由器看到"财务"关键词后直接匹配到 `财务` 工具，忽略了"删除"意图。结果调用 `finance_module.process_command()` 失败。

**根因**：
1. 路由提示词中没有"删除 > 模块关键词"的优先级规则
2. `财务` 工具描述未排除删除场景
3. 降级关键词匹配中 `FINANCE_KW` 检查早于 `DELETE_KW`

## 修复内容

### 1. 路由提示词新增优先级规则

在 `_ROUTE_PROMPT_V2` 顶部新增 **⚠️ 优先级规则** 章节：

```
1. 删除意图优先: 当文字同时包含删除关键词和模块词时，删除意图优先
   例: "删除之前的财务数据" → ask_clarify(不是财务!)
   例: "清空所有记账" → ask_clarify(不是财务!)
2. 先判断是否为删除，再判断模块归属
```

### 2. 工具描述增加排斥规则

| 工具 | 新增规则 |
|------|----------|
| 财务 | `⚠️ 仅当文字中不含删除/清空关键词时才路由到此` |
| 日程管理 | `⚠️ 含"删除"关键词的文字不路由到此` |
| 澄清问询 | 新增 finance target_type 的典型示例 |

### 3. 关键判断规则重写

旧版：简单的"删除分两种"二选一  
新版：**删除意图决策链**（3 步流程）：
1. 检查是否含删除关键词
2. 是 → 目标明确？→ delete_reminder : ask_clarify（推断 target_type）
3. 否 → 继续判断其他意图

### 4. JSON 输出新增 finance 澄清示例

```json
澄清财务:{"tool":"ask_clarify","action":"delete_scope",
  "params":{"target_type":"finance",
  "message":"你是想删除全部财务记录，还是最近一周的？还是最新一条？"},
  "confidence":0.95,"explanation":"模糊删除财务-需确认范围"}
```

### 5. 降级关键词匹配优先级调整

| 旧顺序 | 新顺序 |
|--------|--------|
| FINANCE_KW → CORRECTION_KW → DELETE_KW → SCHEDULE_KW | DELETE_KW → FINANCE_KW → CORRECTION_KW → SCHEDULE_KW |

DELETE_KW 匹配后还检测 finance 上下文关键词（"财务"/"记账"/"账单"/"消费"/"收入"/"记录"），若有则降级为 `ask_clarify(target_type="finance")`。

## 验证

触发场景：
```
"删除之前的财务数据"
  → LLM路由: ask_clarify(target_type="finance")
  → 系统: "你是想删除全部财务记录，还是最近一周的？还是最新一条？"
  → 用户: "全部"
  → _parse_delete_scope → ("all", None)
  → call_tool("财务", "all", _func="delete_by_scope")
  → finance_module.delete_by_scope("all")
  → ✅ 已清空全部 N 条财务记录
```
