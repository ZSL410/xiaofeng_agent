# 财务模块

## 概述

`01_工具模块/财务模块/` — 自然语言记账、查账、删除、财务报告生成。

## 核心功能

### 1. 自然语言记账

```
"记账午餐30元"          → 解析金额/类型/来源 → 存入 local_archive.json
"帮我记一下打车25块"     → 同上
"花了50买书"            → 同上
```

解析引擎：从口语中提取金额、消费类型、来源。

- **金额提取**（v3.9.11）：语义模式，优先取货币词（元/块/钱/角/毛）附近的数字，其次消费词（消费/花了/用了/买了/付了）后，最后取最大数字
- **中文数字**（v3.7.8）：支持六元、十五块、十二块五（十二块五 → 12.5）
- **类型判定**：含 花/买/消费/用/支出 → 支出；含 赚/收/工资/奖金/红包 → 收入；否则默认支出

### 2. 日期解析（v3.9.12-14，LLM 优先）

记账时日期解析三级降级：

```
_parse_date_with_llm()   → ① LLM(qwen2.5:3b) 解析，支持"上周三""上上周周二"等复杂表达
_parse_relative_date()   → ② 正则兜底：今天/昨天/前天/大前天/上周X/上上周X/周X/这个月的X号/上个月
默认今天                 → ③ 解析失败时回退到今天
```

> 查账时日期处理相反（v3.9.17）：**正则 `_parse_relative_date` 优先且覆盖 LLM 结果**，避免 LLM 幻觉日期。

### 3. 查账

```
"查账这个月"            → 汇总本月消费
"花了多少钱"             → 查询总支出
"上周三花了多少"         → 精确日期查询
"把它们详细列举一下"     → 沿用上一轮筛选条件 + 逐条明细（v3.9.18 上下文继承）
```

支持两种查询模式：
- **Mode B（结构化）**：路由层传入结构化参数（date/date_range/source/amount_min/max）
- **Mode C（自然语言）**：LLM 解析查询意图

**查询日期标签**：今天 / 昨天 / 本周 / 上周 / 本月 / 上个月（`TIME_TO_RANGE` 映射）

**查询上下文继承**（v3.9.18）：当用户使用指代词（"它们"/"这些"/"刚才的"/"之前的"）或纯格式请求（"详细点"），且当前查询无筛选条件时，自动沿用上一轮查询的 date/date_range/source/scope。

**统计聚合**：`sum`（合计）/ `count`（笔数）/ `avg`（平均）/ `max`（最大）/ `min`（最小）

**排序规则**：
- 存储与默认展示：**日期降序 + 时间升序**（`_sort_records`）
- 查询可选排序：`amount_desc` / `amount_asc` / `date_desc` / `date_asc`

### 4. 删除

支持范围删除（`delete_by_scope`）：`all`（清空）/ `last_week`（最近一周）/ `today`（今天）/ `latest`（最新一条）/ `keyword`（按关键词）

### 5. 财务报告生成

`finance_module.generate_report()` 纯 Python 聚合生成报告（v3.13.18 起，不依赖 Ollama；v3.13.20 起支持图表与 Excel 导出）：

```bash
# Word 报告（默认，含收支趋势图表）
python -c "import sys; sys.path.insert(0, '01_工具模块/财务模块'); import finance_module; finance_module.generate_report()"
# 仅导出 Excel
python -c "import sys; sys.path.insert(0, '01_工具模块/财务模块'); import finance_module; finance_module.generate_report(format='excel')"
# Word + Excel 同时生成
python -c "import sys; sys.path.insert(0, '01_工具模块/财务模块'); import finance_module; finance_module.generate_report(format='both')"
```

- 读取 `local_archive.json`
- 汇总：总支出 / 总收入 / 结余（默认范围 = 今日，今日无数据则取最近有数据日）
- 交易明细：近 3 天记录（≤30 条）
- **收支趋势图表**（v3.13.20）：近 7 天 + 近 30 天各一张折线（趋势）与柱状（对比）图，展示支出/收入/结余三指标，位于期间对比表前；matplotlib 缺失或渲染失败自动跳过并注明「（图表生成失败，请查看表格数据）」，不阻塞报告
- 期间对比：本周 vs 上周、本月 vs 上月（全量数据）
- 分类统计：今日 + 近 3 天支出占比
- 支持 `scope` 参数：`"default"`（默认）/ `"today"` / `"week"` / `"month"` / `"all"`（全量）
- 支持 `format` 参数（v3.13.20）：`"docx"`（默认，五段式 Word）/ `"excel"`（仅 Excel）/ `"both"`（Word + Excel 同时生成；openpyxl 缺失时 Excel 失败但仍返回 Word，部分成功）
- **Excel 导出**（v3.13.20）：`generate_excel(data=None, output_path=None, scope="default")` → 四工作表工作簿（`Summary` 收支汇总 / `Category` 分类统计+占比 / `Comparison` 期间对比 / `Detail` 交易明细全量按日期降序），口径与 Word 报告一致
- 输出到项目根目录 `每日财务/`（旧版 LLM 独立脚本已归档到 `docs/99_归档/generate_report.py`）

## 数据文件

| 文件 | 用途 |
|------|------|
| `local_archive.json` | 记账记录（唯一存储，15 字段标准格式） |
| `memory.json` | ⚠️ 遗留文件，**无任何代码读取/写入**，仅为示例数据，可忽略 |

## 记录字段标准（v3.9.24）

所有记录自动填充标准字段（代码注释称"11 个标准字段"，实际含辅助字段共 **15 键**）：

| 字段 | 说明 |
|------|------|
| `id` | 唯一标识，`finance_{YYYYMMDD}_{HHMM}_{6位随机}` |
| `type` | `expense` / `income` |
| `date` | `YYYY-MM-DD` |
| `time` | `HH:MM` |
| `datetime` | `YYYY-MM-DDTHH:MM:00` |
| `period` | 时段时间标签（凌晨/早上/上午/中午/下午/晚上/深夜） |
| `amount` | 金额（int/float） |
| `source` | 来源（口语原文，如"饭""日常消费"） |
| `category` | 自动推断的分类 |
| `content` | 自动生成的摘要（见下方模板） |
| `detail` | 明细（写入时为 null，预留） |
| `created_at` | 创建时间 |
| `updated_at` | 更新时间（写入时为 null，预留） |
| `_original_text` | 用户原始输入（调试/兼容） |
| `_time_ref` | 时间参考词（调试/兼容） |

> 旧格式记录首次加载自动迁移补全字段（`_migrate_to_standard_format`，v3.9.24），不丢失数据。

## 内容生成模板（`_generate_content`）

记录时自动生成 `content` 摘要：

| 条件 | 模板 |
|------|------|
| 有时段 + 来源 | `{period}{source}花了{amount}元`（如"中午饭花了10元"） |
| 仅来源 | `{source}花了{amount}元` |
| 仅时段 | `{period}日常消费{amount}元` |
| 均无 | `日常消费{amount}元` |

查询回复由上层 `_generate_tool_reply` 统一拼装（含追问，见对话系统文档）。
