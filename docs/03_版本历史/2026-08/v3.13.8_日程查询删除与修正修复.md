# v3.13.8 — 日程模块查询/删除/修正修复

> **日期**：2026-08-19 ｜ **类型**：🐛 修复 —— 日程查询误判 / 代办识别 / 日程按时间删除 / 提醒修正

## 背景

Phase 5（日程模块）测试发现 4 个问题：

1. **「显示所有待办」被反问「请问是什么类型的日程？」**——查询被当成"有+日程词"添加。
2. **「代办」返回使用说明**——"代办"（"待办"常见缩写/错别字）未作为待办查询触发词。
3. **「删除今天的日程数据」返回「没有找到匹配」**——日程按时间删除落入关键词搜索。
4. **「把它改成五分钟」返回澄清**——3b 未识别"把它改成"为修正意图。

## 根因分析

### Issue 1："有"字符误匹配

预路由 (G) 与 `schedule_module.process_command` 的"有+日程词"正则均为
`有\s*...\s*(待办|...)`。**"显示所有待办"中的"有"（"所有"里的"有"）**被当独立"有"
匹配，误判为"添加"，又因无日期时间而反问类型。

### Issue 2："代办"缺触发词

查询分支（`process_command` / `query_schedule` 路由）只认"待办"，不认"代办"。
裸"代办"无任何匹配 → 落到使用说明。

### Issue 3：日程删除无按时间分支

v3.13.7 的删除预路由 (N) 只覆盖财务；"删除今天的日程数据"（target=schedule, scope=today）
落到 3b → `delete_reminder_by_query` 按文本搜索 → 找不到。

### Issue 4：修正意图无确定性触发

3b 的 correct 触发词为"不是X是Y/说错了/改一下/应该是"，不含"把它改成X分钟"。
（补充：正则取数 `\d` 不匹配中文数字，"五分钟"需先规范化。）

## 修复内容

### `schedule_module.py`

1. **查询排除词**：`_HAS_QUERY_NOISE_RE` 补 显示/查看/列出/展示/查询/查一下/所有/全部
   ——"显示所有待办"不再被"有+日程词"劫持，落到查询分支列出待办。
2. **"代办"触发**：查询分支关键词、添加待办正则、HAS_TODO_WORD_RE 均补"代办"。

### `脑.py`

3. **(G) 预路由**：`_G_EXCL_RE` 补 显示/查看/列出/展示/查询/查一下/所有/全部，
   `_G_ITEM_RE` 补"代办"。
4. **(N) 删除预路由扩展**：target=schedule 且范围（all/today/last_week/latest）→
   `_pending_delete_confirm` 确认后 `delete_by_scope`（"删除今天的日程数据"不再落入关键词）。
5. **(O) 提醒修正预路由**（新增）：`把它改成X分钟/改成3点/调成半小时` →
   先 `_normalize_chinese_numbers` 规范化中文数字，提取 `time_offset`/`absolute_time`，
   调 `modify_last_reminder`。排除 删除/记住 等意图。
6. **(P) 日程查询预路由**（新增）：裸"代办/待办/显示所有待办/所有待办/日程/事件"等 →
   `query_schedule`。不匹配 添加/删除/记住 前缀。
7. **3b 提示词**：schedule target 触发词补"代办"。
