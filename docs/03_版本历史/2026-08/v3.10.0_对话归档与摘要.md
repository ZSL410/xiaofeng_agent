# v3.10.0 — 对话归档与摘要（记忆系统 Phase 1）

> **日期**：2026-08-11 ｜ **类型**：📚 记忆系统新子系统（对话归档）

## 背景

v3.9.29 完成记忆存储规范化后，记忆系统只存事实和工具操作，**不存对话内容**：无法回忆"之前说了什么"，用户追问细节时无上下文可用。本版本是记忆系统分层架构（L0-L3 + 渐进式披露）的 **Phase 1**：为每一轮对话建立持久化记录（原文 + 摘要），为 Phase 2 的"摘要先行、按需展开"注入策略打基础。

## 架构定位

| 存储 | 内容 | 生命周期 |
|------|------|----------|
| `短期记忆.json`（L0，保持不变） | 最近 20 轮对话 | 会话级，用于 prompt 注入快速通道 |
| `对话归档.json`（新增，L1） | 全量对话原文 + 摘要 | 持久化，按时间检索 |

两者通过 `dialogue_id`（会话 ID）关联。**短期记忆行为完全不变**（本版本为增量修改）。

## 变更内容

### 1. 新增 `00_核心主体/记忆/对话归档.json`

独立 schema（不复用 memory.json 15 字段）：

| 字段 | 说明 |
|------|------|
| `id` | `dialogue_YYYYMMDD_HHMM_随机码` |
| `dialogue_id` | 会话 ID `session_YYYYMMDD_HHMM_xxx`，同一会话共享 |
| `role` | `user` / `assistant` |
| `original_text` | 原始对话文本（完整保留） |
| `summary` | 1-2 句摘要（工具轮规则生成 / 纯对话 3b 生成） |
| `tags` | 关键词标签（基础版关键词提取） |
| `timestamp` | 完整时间戳（秒级） |
| `mood` | 情绪标签（预留，Phase 6 自动检测） |
| `related_memory_ids` | 关联记忆 ID（预留，指向 memory.json 条目） |
| `created_at` | 创建时间（微秒级，用于排序） |

排序：`created_at` 降序（最新在前）。

### 2. 新增接口（`记忆引擎.py`）

| 函数 | 说明 |
|------|------|
| `add_dialogue_record(role, original_text, summary, tags, mood, related_memory_ids)` | 追加对话记录，自动排序 |
| `get_dialogue_summary(limit=3)` | 返回最近 N 轮摘要（供 prompt 注入，Phase 2 用） |
| `expand_dialogue(record_id)` | 按 ID 返回完整原文（Phase 2 按需展开用） |
| `search_dialogue(keyword, limit=5)` | 按关键词搜原文/摘要/标签（Phase 2 用） |

### 3. 主循环接入（`脑.py`）

- 新增 `_record_dialogue_archive(user_input, reply_text, is_tool_round)` 统一钩子
- **所有工具轮**（记账/日程/记忆等）经 `_record_tool_operation` 自动归档，`is_tool_round=True`
- **纯对话轮**（3b 聊天 / 7b 降级 / recall）显式归档，`is_tool_round=False`
- 归档失败不阻塞主流程（try/except 静默降级）

### 4. 摘要策略（三级）

| 场景 | 摘要方式 | 耗时 |
|------|----------|------|
| 工具轮（记账/日程/记忆） | 规则生成（`记账：饭25元` / `添加日程：…` / `记忆：…`），零 LLM | 0ms |
| 纯对话轮 | 3b 轻量摘要（短提示词，**2s 超时**） | <1s |
| 3b 失败降级 | 原文截断（前 20 字） | 0ms |

规则摘要要点：
- 财务：需识别到金额才判为记账（避免"添加任务买牛奶"误判），来源物品表与财务模块 `parse_user_input` 一致
- 日程：删除/修改/查询类用中性"日程："前缀（避免"删除提醒"被标成"添加日程"）
- 助手回复：工具轮 `确认：{截断}`，纯对话轮走 3b

### 5. 标签提取（基础版）

关键词规则：咖啡→咖啡 / 吃饭→餐饮 / 买→购物 / 日程·会议·提醒→日程 / 记账·花了→财务 / 心情·开心·难过→情绪。Phase 3 将升级为正式标签生成。

## 自检结果

| # | 测试 | 结果 |
|---|------|------|
| 1 | `今天吃饭花了25元` → 规则摘要 `记账：饭25元` + 归档记录创建 | ✅ |
| 2 | 纯对话（模拟 3b）→ 3b 摘要归档 | ✅ |
| 3 | `get_dialogue_summary(3)` → 返回最近 3 条，时间降序 | ✅ |
| 4 | `expand_dialogue(id)` → 返回完整 original_text | ✅ |
| 5 | 归档结构匹配 schema（10 字段 + version + 同会话 dialogue_id） | ✅ |

> 自检 **5/5 + 规则摘要 9 例 + 标签 3 例 + 降级 3 例** 通过。测试用临时归档文件隔离，真实数据不受影响。

## 限制与后续

- 归档无容量上限（Phase 1 设计：个人日常使用一年 <10MB）
- `get_dialogue_summary` / `expand_dialogue` / `search_dialogue` 已实现但**未接入对话**（Phase 2 渐进式披露时接入）
- Phase 2 将把 prompt 注入改为"最近 3 轮摘要 + 按需展开"（省约 80% 上下文）
