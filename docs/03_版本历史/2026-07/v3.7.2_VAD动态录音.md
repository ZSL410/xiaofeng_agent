# v3.7.2 VAD 动态录音

> **日期**：2026-07-06 ｜ **类型**：功能改进 ｜ **影响范围**：语音输入模块 (`耳朵.py`)

## 问题

`耳朵.py` 使用固定 5 秒录音时长（`sd.rec(duration=5, blocking=True)`），导致：
- 用户说长句子时被中途截断（如"帮我设置一个明天早上八点的闹钟"）
- 用户说完后仍需等待剩余时长才能开始识别
- 无法区分"用户还在说话"和"用户已说完"

## 解决方案：基于 RMS 能量的 VAD（Voice Activity Detection）

将录音从**固定时长阻塞模式**改为**流式 VAD 动态模式**：

### 核心改动

#### 1. 配置常量（新增）

| 常量 | 默认值 | 说明 |
|------|--------|------|
| `SILENCE_THRESHOLD` | 500 | RMS 能量阈值，低于此值视为静音 |
| `SILENCE_DURATION` | 1.5s | 连续静音多少秒后自动停止 |
| `MAX_RECORD_SECONDS` | 30s | 最大录音时长，超时强制停止 |
| `CHUNK_DURATION` | 0.1s | 每块音频时长，用于 VAD 检测 |

#### 2. `_record_sounddevice()` — 流式重写

**旧版**：`sd.rec(samples, blocking=True)` → 固定 5 秒 → 返回 `bytes | None`

**新版**：`sd.InputStream(callback=...)` → 100ms 块 → VAD 动态停止 → 返回 `(bytes, status)`

```
音频流 → InputStream(callback) → 每 100ms:
  ├─ 追加到 audio_chunks
  ├─ 计算 RMS → 与 SILENCE_THRESHOLD 比较
  ├─ RMS >= 500 → 有语音 → silence_frames=0
  ├─ RMS < 500 且曾检测到语音 → silence_frames++
  │   └─ 连续 15 帧(1.5s) 静音 → raise CallbackStop()
  └─ 总帧数 > 300(30s) → raise CallbackStop()
```

#### 3. `_record_parec()` — VAD 改造

**旧版**：`while time < 5s: chunk = read(640)` → 固定 5 秒

**新版**：`while frames < max: chunk = read(3200)` → VAD 动态停止

每个 0.1s chunk (3200 bytes) 计算 RMS，与 `_record_sounddevice()` 共用 VAD 逻辑。

#### 4. `_compute_rms()` / `_rms_from_array()` — 新增工具函数

两个共享的 RMS 计算函数：
- `_compute_rms(bytes)` → 从 PCM 字节计算（parec 使用）
- `_rms_from_array(ndarray)` → 从 numpy 数组计算（sounddevice 使用）

#### 5. `listen_once()` — 状态处理增强

新增返回状态码处理：
- `"ok"` → 正常录音完成
- `"timeout"` → 超过 30s，返回 `"录音超时,请缩短说话内容"`
- `"no_audio"` → VAD 未检测到语音，返回 `"未检测到语音,请重试"`
- `"error"` → 录音失败，返回 `"录音失败"`

### 依赖

- `sounddevice`（已有）
- `numpy`（已有）
- 无新增外部依赖

### 性能

- `sd.InputStream` 回调模式：仅每 100ms 计算一次 RMS（O(n) 向量运算），远低于持续录音开销
- `parec` 模式：每 0.1s 读取 3200 bytes + RMS 计算，同样低 CPU 占用
- 主线程通过 `time.sleep(0.05)` 轮询，不阻塞
