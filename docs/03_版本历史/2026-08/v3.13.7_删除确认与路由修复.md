# v3.13.7 — 删除确认 + 删除路由 + 语音提示

> **日期**：2026-08-16 ｜ **类型**：🐛 修复 —— 高风险删除确认 / 删除路由误判 / 语音输入提示

## 背景

Phase 4（日程/删除）测试发现 3 个问题：

1. **「删除今天的财务数据」直接执行，无确认**——批量/范围删除是不可恢复操作，应先行确认。
2. **「删除昨天的财务记录」被 3b 误判为记账**——返回"没听懂金额"，因为 3b 看到"财务记录"就归为 record。
3. **按 V 无「正在听」提示**——语音输入无任何前置反馈。

## 根因分析

### Issue 1 & 2：删除依赖 3b，无确定性预路由，且无确认

- 删除完全依赖 3b 路由器（无确定性删除预路由）。3b 对"删除昨天的财务记录"误判为
  record+finance（金额缺失 → "没听懂金额"）。
- 即使 3b 判定正确（"删除今天的财务数据"→ delete+finance+scope=today），
  也直接 `delete_by_scope("today")` 执行，**没有确认步骤**。

### Issue 3：V 键直接 `listen_once()`，无提示、无异常兜底

## 修复内容

### `脑.py`

1. **删除预路由 (N)**（置于 3b 之前）：删除词（删除/删掉/删了/移除/清空/清除/清掉/去掉）
   + 非否定 → 解析范围与目标：
   - 高风险财务范围（all/today/last_week/yesterday/latest）→ 设置 `_pending_delete_confirm`，
     询问「确认删除X的财务记录吗？此操作不可恢复。」；用户确认后才执行。
   - "昨天/昨日"→ scope=yesterday（`_parse_delete_scope` 未覆盖，落入 keyword）。
   - 序号删除（删除待办N）→ 直接 `delete_by_index`（低风险）。
   - 其他（关键词/日程/记忆/目标不明）→ 落到 3b/7b 正常流程。
2. **删除确认状态机 `_pending_delete_confirm`**：确认词（是/对/确认/好…）→ 执行
   `delete_by_scope`；否定词（取消/不删/算了…）→ 取消；其他 → 视为取消。
   删除否定检查（不要删除）同时清除该状态。
3. **3b delete 路径同步接入确认**：`scope_from_params/time` 命中 DIRECT_SCOPES 时
   同样改为先确认，不直接执行。
4. **语音输入提示**：按 V 先打印「🎤 正在听...（说完自动停止，最多 25 秒）」，
   包裹 try/except 兜底，并将「录音失败」并入失败分支。

### `finance_module.py`

- `delete_by_scope` 新增 **yesterday** 范围：删除昨天的记录（此前无此范围，
  "删除昨天"会落入 keyword 找不到目标）。
