# v3.8.2 — 路由层否定词处理规则

**日期**：2026-07-22  
**类型**：修复 (fix) — 保护机制优化第1项  
**影响范围**：`00_核心主体/脑.py` — `_ROUTE_PROMPT_V2` 提示词

## 变更动机

路由层在遇到"删除"关键词时无条件触发删除意图，忽略了用户的前置否定词。例如：

| 用户输入 | 旧行为 | 问题 |
|----------|--------|------|
| "查看所有财务数据，不是删除" | → ask_clarify（删除意图） | 用户明确否定了删除，应判为查询 |
| "不要删数据" | → ask_clarify（删除意图） | "不要"否定了删除动作 |
| "不是想删除，是想看看这个月" | → ask_clarify | 前半句否定删除，后半句表达查询意图 |

这导致系统在用户明确表示"不删除"时仍然执行删除流程，存在安全风险。

## 变更内容

### `_ROUTE_PROMPT_V2` 新增"否定词规则"（最高优先级）

```
## ⚠️ 否定词规则（最高优先级，v3.8.2）

否定词列表: 不 / 没 / 别 / 不是 / 并非 / 不要 / 不用 / 无需 / 没有想 / 不想

处理流程:
1. 首先检查句子中是否有否定词
2. 如果有否定词，标记被否定的意图关键词
3. 被否定的意图 → 排除该意图，重新按其他规则判断
```

**关键设计**:
- 否定词必须修饰意图动词才生效（如"不是删除"→生效；"不是很好，删除吧"→"不是"修饰"好"，不生效）
- 否定后的重判结果 confidence 设为 0.9+（否定明确，信号强）

### 决策链重构

意图决策链从：
```
删除检查 → 模块归属 → 其他意图
```

变为：
```
否定词检查 → 排除否定意图 → 删除检查 → 模块归属 → 其他意图
（优先级最高）              （原有逻辑）
```

### 示例对照

| 用户输入 | 旧判断 | 新判断 |
|----------|--------|--------|
| "查看所有财务数据，不是删除" | ask_clarify | 财务 query（confidence 0.9+） |
| "不要删数据" | ask_clarify | 聊天或其他（排除删除后重判） |
| "删除昨天的记录" | ask_clarify | ask_clarify（无否定词，不变） |
| "不是想删除，是想看看这个月" | ask_clarify | 财务 query（排除删除→判断查询） |
