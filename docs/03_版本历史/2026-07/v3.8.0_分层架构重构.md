# v3.8.0 — 财务模块分层架构重构

**日期**：2026-07-21  
**类型**：重构 (refactor) — **BREAKING**（财务模块 API 变更）  
**影响范围**：`01_工具模块/财务模块/finance_module.py`、`00_核心主体/脑.py`

## 变更动机

财务模块的 `process_command()` 和 `delete_by_scope()` 原先直接返回用户可见的字符串（如 `"✅ 已记录:{...}"`），存在以下问题：

1. **返回格式不统一**：`process_command` 返回原始 dict；`delete_by_scope` 返回带 emoji 的字符串
2. **回复逻辑分散**：每个工具模块自己拼装用户可见的回复文字，导致风格不一致、难以维护
3. **无法集中升级**：如果未来想让 LLM 生成个性化回复，需要修改每个工具模块
4. **测试困难**：解析字符串比解析结构化 dict 更容易出错

## 设计原则：分层架构

```
用户输入 → 路由层(脑.py) → 工具模块(数据逻辑) → 返回结构化dict
                                                    ↓
用户 ← 回复层(脑.py) ← _generate_tool_reply() ← 集中组装回复
```

- **工具模块**：只负责数据操作和摘要生成，不拼接用户可见的 emoji/表情/提示语
- **回复层**：集中在 `脑.py` 的 `_generate_tool_reply()`，统一所有工具模块的回复风格
- **可扩展**：未来其他模块（日程、记忆等）只需实现相同的结构化返回格式，即可复用回复层

## 变更内容

### 1. `finance_module.py` — 结构化返回

**`process_command()`** 返回格式（之前是字符串/dict）：

```python
# 成功
{
    "status": "success",
    "type": "expense",           # expense | income
    "data": {
        "amount": 10,
        "source": "饭",
        "date": "2026-07-21",
        "category": "餐饮",     # v3.8.0 新增分类字段
    },
    "summary": "记录今天饭10元"  # 供回复层使用的简短摘要
}

# 错误
{
    "status": "error",
    "message": "没听懂金额，请说清楚一点，比如'今天早上吃饭花了6元'"
}
```

**`delete_by_scope()`** 返回格式（之前是带 emoji 的字符串）：

```python
# 成功
{
    "status": "success",
    "type": "delete",
    "data": {"scope": "all", "count": 5},
    "summary": "清空全部5条财务记录"
}

# 错误
{
    "status": "error",
    "message": "💰 没有财务记录可以删除"
}
```

### 2. 新增辅助函数

| 函数 | 位置 | 说明 |
|------|------|------|
| `CATEGORY_MAP` | finance_module | 来源→分类映射（饭→餐饮、水→饮品等） |
| `_extract_time_ref()` | finance_module | 从原文提取时间参照词（昨天/今天/早上等） |

`parse_user_input()` 返回中新增 `category`、`time_ref`、`original_text` 字段。

### 3. `脑.py` — 集中回复层

新增 `_generate_tool_reply(result, prefix="好的")`：

```python
def _generate_tool_reply(result, prefix="好的"):
    if result["status"] == "error":
        return result["message"]
    # 根据 type 生成自然语言回复
    # expense → "好的，已记录今天饭10元"
    # delete → "明白了，已清空全部5条财务记录"
```

- 兼容旧版字符串返回值：`isinstance(result, dict)` 判断为假时直接透传
- 不同调用场景可传不同 `prefix`：记账用"好的"，删除用"明白了"

### 4. 调用点更新

```python
# 之前
result = call_tool("财务", user_input)
print(result)      # 打印原始 dict
speak(result)      # TTS 朗读原始 dict

# 之后
result = call_tool("财务", user_input)
reply = _generate_tool_reply(result)
print(reply)       # 打印 "好的，已记录今天饭10元"
speak(reply)       # TTS 朗读自然语言
```

删除流程同样更新，传入 `prefix="明白了"`。
