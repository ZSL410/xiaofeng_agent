# v3.13.9 — 关键词搜索格式化（Phase 7, Fix A）

> **日期**：2026-08-21 ｜ **类型**：⚡ 改进 —— 搜索结果"回答生成层"：分组摘要替代原始记录 dump

## 背景

Phase 7（搜索与检索）测试发现：「搜索咖啡」返回的是原始操作日志（"添加待办"/"添加日程"/"确认：…"），
不含真正与咖啡相关的实质内容。根因是搜索模块停留在"数据检索层"——匹配到记录就原样 dump，
没有"回答生成层"来理解用户意图并组织答案。

## 修复内容

### `记忆/记忆引擎.py`

1. **对话噪音过滤扩展**：`search_by_keyword` 的对话噪音前缀 `_SEARCH_NOISE_PREFIXES`
   覆盖 工具操作：/记账：/添加日程：/添加待办：/记忆：/日程： 及确认回声
   （确认：🔍/🟢/⚪/🧠/✅/📋/📅），避免搜索自污染。
2. **`_display_text(record)`**：选取最可读字段——事实用 content，事件优先 detail
   （含具体信息如"添加待办「买咖啡豆」"），通用回声（凌晨添加待办 / 记账）跳过，
   回退 content → title。
3. **`_memory_domain(record)`**：归类 事实/财务/日程/待办/情绪/习惯/对话/其他。
4. **`format_keyword_search(keyword, hits)`**：分组摘要输出；过滤两类噪音——
   - 记忆命中：`_display_text` 为通用回声（无具体信息，仅命中标签）的记录
   - 对话命中：长列表 dump（📅/📋 整块日程/待办回复，>80 字）
   输出格式：`找到N条与「咖啡」相关的记录：\n\n[事实] …\n[待办] …`

### `脑.py`

- 预路由 (C) 与 3b 搜索镜像统一改用 `format_keyword_search`，移除原始 dump 循环。
