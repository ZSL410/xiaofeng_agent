# v3.7.4 — 模糊删除澄清流程

**日期**：2026-07-13  
**类型**：新功能 (feature)  
**影响范围**：`00_核心主体/脑.py`、`01_工具模块/日程模块/schedule_module.py`、`01_工具模块/财务模块/finance_module.py`

## 变更动机

当用户说"删掉之前的数据"或"把之前的删了"时，路由器能识别"删除"意图，但无法提取具体目标（id、时间范围、内容）。旧版直接尝试模糊匹配，通常匹配不到任何内容，返回"没有找到匹配的提醒"，用户体验差。

需要增加一个结构化的澄清流程：当删除请求缺乏明确目标时，系统主动询问删除范围，然后按用户指定的范围执行删除。

## 变更内容

### 1. 新增 `ask_clarify` 意图类型

在路由提示词（`_ROUTE_PROMPT_V2`）中新增第 6 种意图类型：

| 字段 | 值 |
|------|-----|
| `tool` | `"ask_clarify"` |
| `action` | `"delete_scope"` |
| `params.target_type` | `"schedule"` 或 `"finance"` |
| `params.message` | 友好的澄清问句 |

**关键判断规则**：删除类意图分两种情况：
- 有明确目标（具体内容/时间/id）→ `delete_reminder`
- 无明确目标（笼统说"之前的数据"/"清一下"）→ `ask_clarify`

### 2. 澄清状态机

在 `main()` 中新增 `_pending_clarification` 状态变量，与已有的 `_pending_confirmation` 并列：

```
用户: "删掉之前的数据"
  → 路由器: ask_clarify
  → 系统: "你是想删除全部数据，还是最近一周的？还是最新一条？"
用户: "全部"
  → _parse_delete_scope("全部") → ("all", None)
  → 执行 delete_by_scope("all")
  → 系统: "✅ 已清空全部数据: 3 条待办"
```

### 3. `_parse_delete_scope()` 范围解析器

将用户的自然语言回复映射为 5 种删除范围：

| 用户说 | scope |
|--------|-------|
| "全部"、"所有"、"都删了" | `all` |
| "最近一周"、"这周的"、"过去一周" | `last_week` |
| "今天"、"今天的" | `today` |
| "最新一条"、"最后那个" | `latest` |
| "算了"、"取消" | `cancel` |
| 其他（"泡咖啡"） | `keyword` |

同时检测 `target_type` 覆盖："财务的全部删了" → `target_type="finance"`。

### 4. 范围删除函数

#### 日程模块 `delete_by_scope(scope, keyword=None)`

| scope | 行为 |
|-------|------|
| `all` | 删除所有未完成待办 + 所有日程事件（保留已完成待办） |
| `last_week` | 删除最近 7 天内创建的未完成待办和日程 |
| `today` | 删除今天创建的未完成待办和日程 |
| `latest` | 删除最新一条未完成待办（优先）或日程 |
| `keyword` | 复用 `delete_reminder_by_query()` 按内容模糊匹配 |

#### 财务模块 `delete_by_scope(scope, keyword=None)`

| scope | 行为 |
|-------|------|
| `all` | 清空全部财务记录 |
| `last_week` | 删除最近 7 天内的记录 |
| `today` | 删除今天的记录 |
| `latest` | 删除最后一条记录 |
| `keyword` | 按来源/类型字段匹配删除 |

### 5. 路由提示词更新

在 `_ROUTE_PROMPT_V2` 中新增：
- **澄清问询** 章节（含 `ask_clarify` 规则和参数说明）
- **关键判断规则** 章节（删除意图二分法）
- JSON 输出示例行：`澄清:{{"tool":"ask_clarify",...}}`
