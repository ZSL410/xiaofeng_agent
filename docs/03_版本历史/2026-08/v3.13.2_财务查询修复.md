# v3.13.2 — 财务查询修复

> **日期**：2026-08-16 ｜ **类型**：🐛 修复 —— 财务查询时间范围 + 来源过滤

## 背景

Phase 3（财务查询）测试发现 3 个问题：

1. **「本周花了多少」返回空** —— 只查了周一（2026-08-10）那一天
2. **「这个月花了多少」只返回 8 月 1 日数据**（2 笔，35 元）
3. **「吃饭花了多少」返回全部 71 条** —— 没按来源过滤

## 根因分析

### Issue 1 & 2：范围词被当成精确单日

`query_finance`（v3.9.17 逻辑）始终把 `_parse_relative_date(query_text)` 的结果写进
`query_params["date"]`。而 `_parse_relative_date` 对裸「本周/本月」返回的是**范围起点的具体日期**
（本周→周一 2026-08-10，本月→08-01）。`_execute_query` 中 `date`（精确日期）**优先于** `date_range`，
于是范围查询退化为单日查询。

复现数据（2026-08-16）：
- `date=2026-08-10`（周一）→ 0 条；`date_range=this_week` → 22 条 ✅
- `date=2026-08-01` → 2 条；`date_range=this_month` → 30 条 ✅

### Issue 3：来源关键词丢失

3b 路由器 query 意图的提示词**只提取 time/scope，不提取 source**（`_ROUTE_PROMPT_3B`）。
且 params 中的 `raw_text` 字段永远非空 → `query_finance` 的 `has_meaningful` 恒为 True →
永远走 **Mode B 结构化路径**，`_parse_query_nl`（唯一会提取 source 的 LLM 解析）被跳过。
结果 `source` 恒为 null → 无来源过滤 → 返回全部 71 条。

### 附带发现（Issue 4）：`last_month` 英文码落入开区间

修复 Issue 1&2 后暴露的潜伏 bug：`_execute_query` 的闭区间分支只匹配
`date_range in ("last_week", "上个月")`，英文码 `"last_month"` 不命中 → 落入开区间
`>= date_start`（2026-07-01）→ 把 7 月（41 条）+ 8 月（30 条）全部算进「上个月」。
同时 `this_week`/`this_month` 本就是开区间（无 `date_end` 上界）。

## 修复内容

### `finance_module.py` — `query_finance`

- 区分「范围词」与「单日词」：`本周/上周/本月/上个月` → 映射为
  `date_range`（`this_week/last_week/this_month/last_month`）并 `pop("date")` 清除精确日期；
  单日词（今天/昨天/本周二/上周三/X月X日/显式日期）仍走 `date`。
- `_parse_relative_date` 本身不变（记账路径继续用它解析具体日期）。

### `finance_module.py` — `_execute_query`

- 新增 `_SOURCE_HINT_RULES` + `_extract_source_hint(text)`：从查询原文**确定性**提取来源
  过滤标签（最长关键词匹配，越具体越优先：吃饭→饭、咖啡→咖啡、打车→交通…），不依赖 LLM。
- 来源过滤：`source` 参数为空时，用 `_query_text` 兜底提取来源标签。
- 时间范围闭区间化：`this_week`/`this_month` 补齐 `date_end`；过滤分支改为
  `elif date_end:`（有结束日期即闭区间），彻底修复 `last_month` 英文码跨月问题。
