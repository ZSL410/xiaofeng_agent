# v3.9.31 — 记忆路由深度修复

> **日期**：2026-08-11 ｜ **类型**：🧠 Bug 修复（记忆意图确定性预路由）

## 背景

v3.9.30 的路由提示词修复在真实测试中部分生效，但 3b LLM 路由对记忆意图仍不稳定：

| 输入 | v3.9.30 实际 | 期望 |
|------|-------------|------|
| 我叫什么 | recall（答非所问） | chat / memory query |
| 记住我叫霖（首次） | schedule（加了个"叫我"待办） | record + memory |
| 查看今天的记忆 | schedule（帮助文本） | query + memory |
| 查看最近的记忆 | schedule（帮助文本） | query + memory |
| 搜索咖啡 | chat（答了日程提醒） | search + memory |
| 回忆一下昨天的事 | recall | query + memory |

**根因**：记忆意图关键词明确（记住/记忆/回忆/搜索/我是谁），但依赖 3b LLM 判断不稳定。v3.9.27 已用**确定性预路由**解决日程误判，本版本对记忆采用同样策略。

## 变更内容

### 1. 确定性记忆预路由（`脑.py` main 循环，在 LLM 路由之前）

新增 4 类确定性拦截，**完全绕过 LLM**：

| 触发 | 处理 | 示例 |
|------|------|------|
| **(A) 记住/记下/请记住 + 内容** | `add_fact(content)` → record+memory | "记住我叫霖" → 存"我叫霖" |
| **(B) 我是谁/我叫什么/我的名字** | 从记忆检索名字直接回答 | "我叫什么" → "你叫霖呀" |
| **(C) 搜索/搜一下/查找/找一下** | `get_memories` + keyword 过滤 → search+memory | "搜索咖啡" → 命中咖啡记忆 |
| **(D) 查看/显示/回忆/回顾 + 记忆** | `get_memories` + 时间筛选 → query+memory | "查看今天的记忆"、"回忆一下昨天的事" |

- 各拦截均带关键词排除：搜索类排除 日程/会议/待办/提醒/记账/花了（不抢日程/财务意图）
- 记忆操作失败不阻塞对话（try/except 降级为友好回复）

### 2. 3b 路由提示词强化

- **recall 排除规则**：含"记忆/回忆/记住/搜索/查看记忆/名字/我是谁" → 不是 recall
- **记忆查询规则强化**：含"记忆/回忆/回顾" + 查看类 → target 必须为 memory（绝不是 schedule），明确"查看今天的记忆"等示例
- **search 排除规则**：含"日程/会议/待办/提醒/记账/花了" → 不是 search
