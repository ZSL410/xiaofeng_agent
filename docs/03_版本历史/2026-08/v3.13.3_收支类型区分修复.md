# v3.13.3 — 收支类型区分修复

> **日期**：2026-08-16 ｜ **类型**：🐛 修复 —— 支出查询误把收入计入合计

## 背景

Phase 3（财务查询）测试发现：**「今天花了多少」把收入也算进了支出**。

实测数据（2026-08-16）：
- 当天 5 笔支出（饭20 + 饭25 + 饭10 + 咖啡9 + 日常消费2 = **66 元**）+ 1 笔收入（收入来源 5000 元）
- 系统错误返回「共6笔记录，一共5066元」，期望「共5笔支出，合计66元」

## 根因分析

- 3b 路由器把一切财务查询统一归为 `query` 意图，**不区分收支方向**。
- `_execute_query` 的聚合无条件：
  `total_amount = sum(r.get("amount", 0) for r in records)`、`count = len(records)`
  —— 无论 `type` 是 `expense` 还是 `income` 全被合并统计。

## 修复内容

### `finance_module.py` — `_execute_query`

1. **类型意图识别**：依据 `_query_text` 关键词判定查询方向——
   - 收入词（收入/赚了/进账/入账/工资/奖金/红包/到账…）→ `income`
   - 支出词（花了/支出/花费/开销/消费/用了/买了/开支…）→ `expense`
   - 全量词（所有/全部/财务数据/账单/账目/一共/总共/总计…）→ `all`
   - 无命中 → 默认 `expense`（"花了多少"类查询主体）
   - 优先级：收入 > 支出 > 全量（"一共花了多少"仍按支出处理）
2. **类型过滤**：在金额过滤**之前**按 `type_mode` 过滤 `records`，聚合（sum/count/avg/max/min）
   自然只作用于该方向的记录。
3. **收入标注**：支出模式下若该期间存在收入记录，摘要追加
   「。另有 N 笔收入，合计 M 元」；`income`/`all` 模式不加。
4. **空结果措辞**：`count==0` 分支按方向输出「今天没有支出记录 / 没有收入记录」，
   并保留收入标注（如「今天没有支出记录。另有1笔收入5000元」）。
5. **明细模式**：标题改为「共 N 笔支出记录」并追加收入标注。
