# v3.8.3 — 财务意图 query/record 精确分流

**日期**：2026-07-22  
**类型**：修复 (fix)  
**影响范围**：`00_核心主体/脑.py` — `_ROUTE_PROMPT_V2` 财务意图细分规则

## 变更动机

路由层对财务意图的 action 判断存在三类误判：

| 用户输入 | 旧行为 | 问题 |
|----------|--------|------|
| "查看所有财务数据" | → record (process_command) | "查看"是查询词，应走 query |
| "今天的支出是多少" | → record (process_command) | "多少"是查询词，应走 query |
| "删除昨天的记录" | → 财务 record | "删除"应优先于财务，走删除流程 |

根因：旧版路由提示词中"财务" section 过于模糊，`action: null`（即 record）是默认值，LLM 倾向于将其用于所有"看起来像财务"的输入。

## 变更内容

### 1. 财务意图细分规则（完全重写）

旧版（模糊）:
```
有3种操作:
- record(默认): 记账/报销/花了
- query: 查看/查/显示/统计
```

新版（白名单 + 严格规则）:
```
📌 查询意图 (action: "query") — 触发词白名单
"查看"、"查询"、"显示"、"列出"、"统计"、"看看"、"看一下"、
"有没有"、"多少"、"花了多少"、"一共"、"最大"、"最贵"、"最少"、
"列表"、"查一下"、"看一看"

📌 记账意图 (action: "record") — 触发词 + 金额强制
"花了"、"付了"、"消费"、"支出"、"买了"、"花费"、"用了"、"记账"
⚠️ 必须包含金额数字，无金额则不是 record

📌 默认行为:
- 有金额数字 → record
- 无金额、无触发词 → ask_clarify（不要默认 record！）
```

### 2. 删除优先于财务（明确声明）

财务 section 顶部新增：
```
⚠️ 删除意图优先：含"删除/清空"关键词先走删除流程，不路由到此
```

优先级规则第2条改为：
```
删除意图优先于一切：删除优先级高于财务、日程等所有其他意图
```

### 3. 输出格式示例更新

```
旧：
财务:{"tool":"财务","action":null,...}           ← 默认 action=null
财务查询:{"tool":"财务","action":"query",...}

新：
财务记录:{"tool":"财务","action":null,...}       ← 明确是"记录"
财务查询:{"tool":"财务","action":"query",...}    ← 明确是"查询"  
财务无金额:{"tool":"ask_clarify",...}             ← 新增：兜底澄清
```

### 4. 决策链强化

```
旧: 1.否定词 → 2.删除 → 3.其他意图
新: 1.否定词 → 2.删除(优先于一切) → 3.财务(query白名单判定) → 4.其他
```
