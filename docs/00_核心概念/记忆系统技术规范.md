# 记忆系统技术规范

> **版本**：v3.9.24 ｜ **状态**：已投入使用 ｜ **最后更新**：2026-08-05

---

## 1. 概述

### 1.1 升级目标

将晓风的记忆系统从"被动存储"升级为"主动学习"：

```
v3.6.0 模式（当前）:
  用户陈述 → LLM 无感知 → 被动存储到长期记忆.json

v3.7.0 模式（目标）:
  用户陈述 → LLM 提取记忆 → Python 校验 → 写入分类文件
                                    ↓
                     衰减调度 → 置信度动态调整 → 归档
                                    ↓
                         按需注入 Prompt → 主动预判
```

### 1.2 核心设计原则

| 原则 | 说明 |
|------|------|
| **本地逻辑为主，LLM 为辅** | 统计、规则、衰减全部由 Python 处理；LLM 仅负责语义翻译和标签提取 |
| **数据分离** | 事实（facts）、习惯（patterns）、会话摘要（context_summary）三文件独立 |
| **动态衰减** | 遗忘机制保持记忆库精简，避免膨胀 |
| **最小闭环优先** | 先跑通基础流程（写入→衰减→注入），再迭代高级特性 |
| **可扩展预留** | 为向量检索、图谱关联、多模态等未来升级预留字段和抽象接口 |

### 1.3 术语定义

| 术语 | 定义 |
|------|------|
| **事实（Fact）** | 用户直接陈述的静态信息，如偏好、身份、属性 |
| **习惯（Pattern）** | 从历史行为中统计提炼的规律性行为模式 |
| **会话摘要** | 最近 N 轮对话的 LLM 提炼摘要，每 10 轮覆盖更新 |
| **置信度（confidence）** | 0~1 的值，表示模式的可信程度，低于 0.3 触发归档 |
| **衰减** | 随时间流逝自动降低置信度的机制 |

## 2. 数据结构

### 2.1 facts.json — 静态事实库

存储用户直接陈述的事实性信息。

**路径**：`00_核心主体/记忆/facts.json`

**Schema**：
```json
{
  "version": "1.0",
  "updated_at": "2026-06-24T10:00:00",
  "facts": [
    {
      "id": "fact_001",
      "content": "用户习惯喝冰美式咖啡",
      "category": "偏好",
      "source": "对话",
      "pinned": true,
      "created_at": "2026-06-24T10:00:00",
      "updated_at": "2026-06-24T10:00:00",
      "embedding": null,
      "importance": 0.8
    }
  ]
}
```

**字段说明**：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `id` | string | ✓ | 唯一标识，格式 `fact_{序号}` |
| `content` | string | ✓ | 事实内容，一句完整陈述 |
| `category` | string | ✓ | 分类：`偏好` / `身份` / `技能` / `习惯` / `其他` |
| `source` | string | ✓ | 来源：`对话` / `提炼` / `用户确认` |
| `pinned` | boolean | ✓ | 是否固定注入 Prompt |
| `created_at` | ISO8601 | ✓ | 创建时间 |
| `updated_at` | ISO8601 | ✓ | 最后更新时间 |
| `embedding` | float[] \| null | | 向量预留（v3.8.0+ 语义检索用） |
| `importance` | float | ✓ | 重要性 0~1，综合用户反馈自动调整 |

**分类枚举**：
- `偏好`：口味、风格、习惯偏好
- `身份`：职业、角色、关系
- `技能`：掌握的技能、学习中的领域
- `习惯`：日常行为习惯（区别于 patterns 的统计提炼）
- `其他`：未归类的杂项事实

### 2.2 patterns.json — 动态习惯库

存储从历史行为中提炼的习惯规律。

**路径**：`00_核心主体/记忆/patterns.json`

**Schema**：
```json
{
  "version": "1.0",
  "updated_at": "2026-06-24T10:00:00",
  "patterns": [
    {
      "id": "pattern_001",
      "content": "每天上午8:00-9:00之间设置泡咖啡提醒",
      "type": "time_based",
      "frequency": 3,
      "confidence": 0.85,
      "last_trigger": "2026-06-24T08:00:00",
      "created_at": "2026-06-20T10:00:00",
      "embedding": null,
      "related_to": [],
      "relation_types": [],
      "rejected": false,
      "archived": false
    }
  ]
}
```

**字段说明**：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `id` | string | ✓ | 唯一标识，格式 `pattern_{序号}` |
| `content` | string | ✓ | 习惯描述 |
| `type` | string | ✓ | 类型：`time_based` / `interval` / `association` |
| `frequency` | int | ✓ | 触发频次 |
| `confidence` | float | ✓ | 置信度 0~1 |
| `last_trigger` | ISO8601 | | 最近一次触发时间 |
| `created_at` | ISO8601 | ✓ | 首次发现时间 |
| `embedding` | float[] \| null | | 向量预留 |
| `related_to` | string[] | | 关联的记忆 ID 列表 |
| `relation_types` | string[] | | 关系类型：`temporal` / `causal` / `semantic` |
| `rejected` | boolean | | 用户是否明确拒绝此规律 |
| `archived` | boolean | | 是否已归档（置信度过低且长期未触发） |

### 2.3 context_summary.txt — 会话摘要

纯文本格式的对话摘要，用于 Prompt 注入。

**路径**：`00_核心主体/记忆/context_summary.txt`

**格式**：
```
用户是AI开发学习者，正在构建个人智能体"晓风"。
当前偏好：简短回答，直接反馈。
近期话题：记忆系统升级、日程模块修复。
```

**生成规则**：
- 每满 10 轮对话由 LLM 生成一次
- **覆盖写入**（不是追加），保持文件精简
- 上限 500 字符

### 2.4 向后兼容

v3.6.0 的 `长期记忆.json` 数据自动迁移：
- `长期记忆.json` 中的 `patterns` 数组 → 迁入 `patterns.json`
- 迁移完成后保留原文件作为备份，后续不再读写

## 3. 核心机制

### 3.1 写入机制：LLM 提取 + Python 校验

```
用户输入 "我喜欢喝冰美式"
        ↓
   LLM 判断是否为记忆材料
        ↓
   输出结构化 JSON：
   {"type": "fact", "content": "用户喜欢喝冰美式咖啡",
    "category": "偏好", "importance": 0.8}
        ↓
   Python 层校验：
   - 分类合法性检查（是否在枚举范围内）
   - 内容重复检测（相似度 > 0.85 则合并）
   - 格式完整性检查（必填字段是否齐全）
        ↓
   校验通过 → 写入 facts.json，合并相似条目
   校验失败 → 记录日志，丢弃
```

**重复检测算法**：
- 简单子串匹配：已存在完全相同内容 → 跳过
- 相似度计算：基于公共子串比例，超过 0.85 则合并（更新 importance 取最大值）

**LLM 提取 Prompt 模板**：
```
你是记忆提取器。分析用户输入，判断是否包含值得长期记忆的信息。

如果是记忆材料，输出 JSON：
{"type":"fact","content":"...","category":"偏好|身份|技能|习惯|其他","importance":0.0~1.0}
如果是习惯规律，输出：
{"type":"pattern","content":"...","pattern_type":"time_based|interval|association","confidence":0.0~1.0}
如果不是记忆材料，输出：
{"type":"none"}

只输出 JSON，不要其他内容。
用户输入：{user_input}
```

### 3.2 衰减机制：纯 Python 定时任务

**触发方式**：
1. 随主程序启动时检查（每日一次）
2. 用户手动触发（"整理记忆"）

**衰减规则**：

| 条件 | 操作 |
|------|------|
| `last_trigger > 30天` | `confidence *= 0.95`（每日一次） |
| `confidence < 0.3` 且 `last_trigger > 60天` | 标记 `archived: true` |
| `rejected = true` | 不衰减（已在 reject 时处理） |

**实现细节**：
- 每日只执行一次（检查 `last_decay` 日期字段）
- 衰减操作：逐条遍历 → 计算天数差 → 按规则衰减
- 归档操作：将 `archived: true` 的条目从活跃列表中移除，写入 `patterns_archive.json`

### 3.3 检索与注入机制

**注入分层**：

| 层级 | 内容 | 上限 | 触发条件 |
|------|------|------|----------|
| 必注入 | `context_summary.txt` + pinned facts | 5 条事实 | 始终注入 |
| 按需注入 | 高置信度 patterns（confidence > 0.5） | 5 条 | 用户提及"提醒/定时/日程/叫我"等关键词 |
| 全量注入 | 全部 pinned facts + 全部高置信度 patterns | 无限制（受 token 上限控制） | 用户明确要求"查看记忆" |

**注入格式**（纯文本，注入到 system prompt）：
```
[用户记忆]
- (事实) 用户喜欢喝冰美式咖啡
- (事实) 用户AI开发学习者
[近期摘要]
用户正在构建个人智能体"晓风"。偏好简短回答。
[行为习惯]
- 每天上午8:00-9:00 泡咖啡 (置信度:85%)
```

**Token 控制**：
- 注入总上限：2000 tokens（约 500 中文字符）
- 超限时按 importance/confidence 降序截断
- `_estimate_tokens()` 辅助函数：中文约 1 char ≈ 1.5 tokens

## 4. 接口设计

### 4.1 记忆引擎核心接口

```python
# ========== 写入接口 ==========

def add_fact(content: str, category: str = "其他",
             pinned: bool = False, importance: float = 0.5,
             source: str = "对话") -> dict:
    """写入事实记忆，返回 {"status": "added"|"merged"|"skipped", "id": str}"""

def add_pattern(content: str, pattern_type: str = "time_based",
                confidence: float = 0.3) -> dict:
    """写入习惯记忆，返回 {"status": "added"|"merged", "id": str}"""

def update_confidence(pattern_id: str, delta: float) -> dict:
    """更新置信度，返回 {"status": "ok"|"not_found", "new_confidence": float}"""

def update_importance(fact_id: str, delta: float) -> dict:
    """更新事实重要性，返回 {"status": "ok"|"not_found", "new_importance": float}"""

# ========== 检索接口 ==========

def get_pinned_facts(limit: int = 5) -> list[dict]:
    """获取固定事实（按 importance 降序）"""

def get_high_confidence_patterns(min_confidence: float = 0.5,
                                  limit: int = 5) -> list[dict]:
    """获取高置信度习惯（按 confidence 降序）"""

def get_context_summary() -> str:
    """获取会话摘要文本"""

# ========== 衰减接口 ==========

def run_decay() -> dict:
    """执行置信度衰减，返回 {"decayed": int, "archived": int, "kept": int}"""

def archive_expired() -> dict:
    """归档过期记忆，返回 {"archived": int}"""

# ========== 维护接口 ==========

def rebuild_context_summary(history: list[dict]) -> str:
    """根据最近对话历史，通过 LLM 重新生成会话摘要"""

def merge_similar_facts() -> dict:
    """合并相似事实，返回 {"merged": int, "skipped": int}"""

def get_memory_stats() -> dict:
    """获取记忆系统统计：{facts_count, patterns_count, active_patterns, archived_patterns}"""
```

### 4.2 存储抽象类（未来可替换）

```python
from abc import ABC, abstractmethod

class MemoryStorage(ABC):
    @abstractmethod
    def read(self, key: str) -> dict | list | str: ...
    @abstractmethod
    def write(self, key: str, value) -> None: ...
    @abstractmethod
    def search(self, query: str) -> list: ...
    @abstractmethod
    def delete(self, key: str) -> bool: ...
```

v3.7.0 使用 `JSONFileStorage` 作为默认实现。未来可替换为 SQLite、向量数据库等。

## 5. 事件系统预留

在 `patterns.json` 中预留事件钩子字段，供后续版本实现发布-订阅模式：

| 事件名 | 触发条件 | 预留字段 |
|--------|----------|----------|
| `on_pattern_formed` | 同一 pattern 连续触发 ≥3 次 | `patterns[].frequency >= 3` |
| `on_pattern_decayed` | confidence 降至 0.3 以下 | `confidence < 0.3` |
| `on_fact_confirmed` | 用户主动肯定某个事实 | `source == "用户确认"` |

v3.7.0 中通过日志记录这些事件，不创建正式的 EventBus。
