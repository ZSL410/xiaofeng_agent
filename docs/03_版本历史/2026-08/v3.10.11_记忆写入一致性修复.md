# v3.10.11 — 记忆写入一致性修复（新记忆创建即带生命周期字段）

> **日期**：2026-08-15 ｜ **类型**：🐛 记忆写入一致性

## 背景

测试发现两条相似消费输入产生不同结果：一条的记忆记录带 `confidence`/`retrieved_count`，
另一条却没有 → 置信度机制无法对这些记录生效，记忆写入行为不一致。

## 根因

`add_memory_event`（及 `_fact_to_memory`/`_pattern_to_memory`）创建的记忆记录**只有 15 字段基础结构**，
**不含生命周期字段** `confidence` / `tier` / `retrieved_count` / `last_retrieved`。

这些字段只在模块 import 时由 `backfill_memory_lifecycle()` 统一补齐——因此：
- 交易发生 → 立即创建的记忆记录**缺**置信度与检索计数；
- 直到下一次 `脑.py` 启动（import 触发 backfill）才被补上。

用户按"应带 `retrieved_count` 和 `confidence` 字段"验证时，刚创建的记录不满足 → 表现为"记忆写入不一致/缺失"。

## 变更内容（`记忆引擎.py`）

在**所有记忆创建路径**中，构建记录后立即调用 `_init_memory_lifecycle(record)`：

- `add_memory_event` — 财务/日程记账、手动记忆写入
- `_fact_to_memory` — fact 同步到记忆库
- `_pattern_to_memory` — habit 同步到记忆库

效果：每条新记忆**创建即带** `confidence`（缺省按 importance/10）、`tier=L1`、`retrieved_count=0`、
`last_retrieved=创建日期`。置信度机制对所有记录一致生效，不再依赖后续 import 兜底。
