# v3.13.6 — 收支合计明细 + 收入确认措辞修复

> **日期**：2026-08-16 ｜ **类型**：🐛 修复 —— 明细模式收支分计 + 收入记账确认语

## 背景

Phase 3（财务查询）测试发现 2 个问题：

1. **「显示所有财务记录」总合计混算收支**——明细模式下全量查询只给一个总数
   （合计：5834.5元），未区分支出/收入。
2. **收入记账确认语仍出现「花的」**——v3.13.5 已修但只覆盖了 `data` 带 `type` 的场景，
   3b 路由路径下仍输出「已记下你今天收入花的5块钱」。

## 根因分析

### Issue 1：明细模式全量查询单总数

`_execute_query` 的明细分支统一 `total_amt = sum(amount for r in records)`。
全量模式（`type_mode=="all"`）下 records 含支出+收入 → 一个混合总数。
「显示所有财务记录」命中 detail 模式（3b 可能给 detail=true）即复现。

### Issue 2：`_fmt_record` 读不到 type

`process_command` 把 `type` 放在**结果顶层**（`result["type"]`），
`data` 字典内没有 `type` 键。而 `_fmt_record(summary, data)` 读的是
`data.get("type", "expense")` → 恒为 expense → 收入也被拼成「花的X元」。
v3.13.5 只改了措辞模板，没解决 type 传不到函数的问题。

## 修复内容

### `脑.py` — `_fmt_record`

- 签名增加 `record_type` 参数（由调用方传 `result["type"]`，位于结果顶层）。
- 调用点 `_fmt_record(summary, data, rtype)`。
- `record_type` 为 None 时仍回退 `data.get("type")`（兼容其他调用）。

### `finance_module.py` — `_execute_query` 明细分支

- 全量模式（`type_mode=="all"`）明细汇总分别输出：
  「支出合计：X元（N笔）；收入合计：Y元（M笔）」。
- 单一方向查询仍输出原「合计：X元」。
