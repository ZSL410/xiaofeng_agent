# v3.9.26 — 路由与执行修复

> **日期**：2026-08-06 ｜ **类型**：🐛 Bug 修复（路由 + 日程执行）

## 背景

日程模块在测试中发现多个路由与执行问题：任务添加被误路由到财务、删除按范围误删、事件查询不识别、本周筛选失效、模糊时间无法解析。

## 变更内容

### P0-1: "添加任务买牛奶" 误路由到财务

**问题**：3b 路由器将 `record` 意图的 target 固定为 `finance`，导致含"任务/待办"的添加请求走财务记账。

**修复**（`脑.py` `_ROUTE_PROMPT_3B`）：
- record 规则新增 target 推断优先级：含 任务/待办/提醒/日程/事件/叫我 → **target 必须为 schedule**（即便同时含"买了"等财务词）
- target 推断优先级最高规则同步更新
- 新增示例：`"添加任务买牛奶" → {"intent":"record","target":"schedule","params":{...,"content":"买牛奶"}}`
- 主循环 record 处理器按 target 分流：`target=schedule` → 调 `日程` 模块，否则 → `财务` 模块

### P0-2: "删除待办1" 误删全部

**问题**：`delete` 处理器对 schedule 一律走 `delete_by_scope`，含序号（"待办1"）时误触发批量删除。

**修复**（`脑.py` + `schedule_module.py`）：
- 3b 路由 delete 规则新增**序号删除规则**：`删除待办N`/`删除任务N` → scope 填 `keyword`（值为序号），**绝不**因含数字判为 today/all
- 主循环 schedule delete 处理器：先匹配 `删除(待办|任务|todo)(\d+)` → 调 `delete_by_index(idx)` 只删一条；仅当用户明确说 今天/所有/全部/最近 等范围词才走 `delete_by_scope`
- 新增 `delete_by_index(index, record_type="todo")` 函数，按展示顺序（未完成优先）解析序号或字符串 ID

### P1-1: "显示所有事件" 返回使用说明

**问题**：路由器不识别"事件"为查询触发词。

**修复**：查询触发词列表补充"事件"；target 推断补充"事件"→schedule；降级关键词 `SCHEDULE_KW` 补充"事件"。

### P1-2: "查看本周的日程" 显示全部

**问题**：`query_schedule` 时间筛选未正确应用——无到期日期的待办被无条件包含，且无日期待办在每次加载时被误迁移成今天。

**修复**（`schedule_module.py`）：
- 指定时间筛选时，无日期待办（`date` 为空）不纳入结果；仅无 time 筛选（显示全部）时包含
- `_is_standard_record` 改为以 `schedule_` 前缀 ID 为迁移标记（不再要求 `datetime` 非空，否则无日期待办被反复迁移）
- 迁移逻辑：无日期记录保留空 `date`（不默认今天）

### P2-1: "一会儿提醒我" 时间解析失败

**问题**：自然语言模糊时间"一会儿"未被解析，回退到 1 分钟兜底。

**修复**（`schedule_module.py`）：
- `_parse_time` 新增"一会儿/待会儿/过会儿/等会儿/稍后" → 默认 **5 分钟后**
- `_has_time_pattern` 同步补充模糊时间模式
