# v3.9.27 — 路由鲁棒性修复

> **日期**：2026-08-07 ｜ **类型**：🛡️ Bug 修复（路由鲁棒性 + 确定性兜底）

## 背景

v3.9.26 的路由提示词修复在实际测试中未完全生效——LLM 路由（qwen2.5:3b）对部分指令仍会误判。本版本从"依赖 LLM 提示词"转向"确定性预路由 + 多级兜底"，确保关键指令不依赖 LLM 输出质量。

## 变更内容

### P0-1: "一会儿/等一会儿" 时间解析失败

**根因**：3b 路由输出 schema 不含 `raw_text`，`add_reminder_from_params` 拿不到原始输入，跳过了 `_parse_time` 兜底，直接落入 1 分钟兜底。

**修复**：
- 3b 路由输出 schema 补充 `raw_text` 字段
- `remind` 处理器调用 `add_reminder_from_params` 前强制注入 `raw_text=user_input`
- `add_reminder_from_params` 新增**模糊时间词防御**：原文含 一会儿/待会儿/过会儿/等会儿/稍后 → `time_offset` 强制为 5（即使 LLM 误判为 1）
- 3b 路由 remind 规则补充 "一会儿"→5 分钟映射
- 调度模块 `_parse_time` 已支持 "一会儿"（v3.9.26）

### P0-2: "添加会议明天下午3点" 被路由到财务

**根因**：3b 路由的 schedule 关键词列表不含"会议"，"添加会议…"被误判为财务记账（amount 被幻觉为 30）。

**修复**：
- 新增**确定性预路由**：在调用 LLM 路由前，检测 `添加/新增/安排/创建/预约 + 会议|事件|日程|约会|聚会|面试|上课|活动|任务|待办` → 直接走日程模块，**完全绕过 LLM**
- 3b 路由 record 规则 + target 推断优先级补充 会议/约会/聚会/面试/上课/活动
- 新增示例 `"添加会议明天下午3点" → record+schedule`

### P0-3: "删除待办1" 批量删除今天数据

**根因**：序号删除检查位于 `target==schedule` 分支内，LLM 误判 target（如 finance）或返回 scope="today" 时不会触发。

**修复**：
- **序号删除前置拦截**：`删除/删掉/移除/取消/清掉 + 待办|任务|todo + 数字` 在 target 分发**之前**拦截，直接调 `delete_by_index`
- 降级路径（V2 路由）的 `delete_reminder` 改为走 `process_command`（支持序号 + 模糊删除）

### P0-4: "查看本周的日程" 显示历史旧数据

**根因**：3b 路由未提取 `time=this_week`（返回 time=null / scope=all），`query_schedule` 退化为显示全部。

**修复**：
- `query_schedule` 新增**兜底时间推断**：路由层未传 time 时，从用户输入关键词推断（本周/这周 → this_week，今天 → today，昨天 → yesterday，上周 → last_week，本月 → this_month）
- 这样即使 LLM 未提取时间，也能正确过滤到本周（排除上周/上月旧数据）
