# v3.10.8 — 记忆系统 Phase 4：置信度衰减 + 记忆整合（L1→L2）

> **日期**：2026-08-13 ｜ **类型**：⚡ 记忆系统 Phase 4（置信度生命周期 + L1→L2 提升 + 归档）

## 背景

Phase 3 已实现标签与时间索引。此时记忆库虽带 `confidence`（仅 3 条习惯记录）与 `importance`，
但缺少生命周期管理：没有层级（L1/L2）、没有检索跟踪、没有衰减与归档机制——记忆只增不减，长期累积噪音。

## 变更内容

### 1. 生命周期字段补齐（`记忆引擎.py`）

| 字段 | 缺省规则 | 说明 |
|------|----------|------|
| `tier` | `"L1"` | 记忆层级：L1 情景 / L2 语义长期（原数据无此字段，按 additive 补齐） |
| `confidence` | `importance/10` | 置信度 0~1（原数据仅习惯记录有此字段） |
| `last_retrieved` | `created_at` 日期 | 最近检索日，缺省取创建日（避免创建即开始衰减） |
| `retrieved_count` | `0` | 检索次数 |

`backfill_memory_lifecycle()` 启动时补齐，幂等。首跑后 44 条记忆全部补齐，
其中 pinned 事实「用户喜欢冰美式咖啡」（importance=8 → conf 0.8）自动提升为 L2（正确行为）。

### 2. 置信度衰减（增量式）

- 规则：**每经过一天、记录未检索，confidence -= 0.005**。
- `run_consolidation()` 内部 `_apply_daily_decay` 基于 `memory.json` 元数据 `last_decay_run` 增量计算：
  只对 `[last_decay_run, 今天]` 期间未检索的天数扣减（期间内检索过的记录只扣检索后的天数），
  避免重复扣减与一次性大规模回扣。

### 3. L1→L2 提升（`promote_to_l2` + `_promotion_pass`）

满足任一条件 → `tier="L2"`，confidence 保底 0.8，记录 `promotion_reason` / `promoted_at`：
- **confidence ≥ 0.8**
- **同一实体主题标签出现 ≥ 3 次**（只统计实体主题标签：咖啡/会议/吃饭/运动/饮品/娱乐/阅读/情绪/购物/喝水；
  排除 财务/日程/记忆/聊天/事件/待办 等类型/语义类别标签，避免"事件"类泛化标签批量误提升）

### 4. 归档（`run_archive`）

任一条件满足 → 移入 **`archive/memory_archive.json`**（自动建目录，按 id 去重追加），从主库移除：
- confidence < 0.2
- 距 last_retrieved 超过 90 天

记录 `archived_at` / `archive_reason`。

### 5. 检索提升（`record_retrieval`）

每次检索展示：`retrieved_count +1`，`confidence +0.05`（封顶 1.0），`last_retrieved` 更新为今天。
脑.py 预路由 (C)(D)(I) 与 3b 搜索/记忆查询处理器在展示结果时调用 `_boost_memory_retrieval`。

### 6. 每日自动维护（`_maybe_run_daily_maintenance`）

模块启动时执行 `run_consolidation()` + `run_archive()`，按元数据 `last_maintenance` 日期幂等（每天一次）。
