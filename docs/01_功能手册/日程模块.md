# 日程模块

## 概述

`01_工具模块/日程模块/schedule_module.py` — 日程事件管理、待办事项管理、定时提醒，带后台守护线程每 30 秒检查到期提醒。

## 核心功能

### 1. 自然语言提醒

```
"提醒我5分钟后喝水"     → 创建待办：喝水(now+5min)
"26叫我"               → 当前小时:26 提醒
"明天8点叫醒我"         → 明天 08:00 提醒
"半个小时后洗衣服"      → now+30min 提醒
```

时间解析三级降级链：正则 → LLM → 1 分钟后兜底

### 2. 日程事件管理

```
"添加会议明天下午3点"   → 创建日程事件
"删除日程1"            → 删除 ID=1 的日程
"显示今天的日程"        → 列出今日日程
"添加后天出门"          → 按日期创建全天事件（无时间，v3.9.28）
```

支持重复：每天/每周/每月

**自然记录表达（v3.9.28）**——无需"添加/创建"动作词即可记录日程：

```
"后天有日程安排给我记一下" → 添加后天的事件
"后天有个日程"            → 同上
"帮我记一下后天开会"       → 添加后天"开会"事件
"安排一下周日的日程"       → 添加周日事件
```

> 含财务词（花了/买了/消费/元/块）时不视为日程记录（走财务记账）。

### 3. 待办事项管理

```
"添加任务买牛奶"        → 创建待办
"完成任务1"            → 标记完成
"删除任务1"            → 删除待办
"显示待办"             → 列出未完成待办
```

### 4. 删除

支持三种删除方式：

```
"删除待办1" / "删除任务2"    → 按序号删除第 N 条（v3.9.26，绝不批量删）
"把两个小时的那个定时删掉"  → 按时间描述模糊删除（v3.2.0）
"删除泡咖啡那个提醒"        → 按内容匹配删除（v3.2.0）
"删除今天的所有待办"        → 按范围批量删除（今天/所有/全部/最近一周）
```

> 按序号删除由 `delete_by_index()` 实现；按内容/时间由 `delete_reminder_by_query()` 实现；按范围由 `delete_by_scope()` 实现。
>
> **序号一致性（v3.9.28）**：删除序号与展示列表使用**相同排序**（date 降序 + time 升序，未完成优先），"显示所有待办 → 删除待办N"删的就是列表里看到的第 N 条。

### 5. 查询（v3.9.26）

```
"显示所有事件" / "查看事件"   → 列出所有事件（"事件"已加入查询触发词）
"查看本周的日程"             → 只显示本周（周一~周日）的日程和待办
"显示今天的待办"             → 只显示今天的待办
"显示待办"                   → 显示全部待办（含无日期待办）
```

> 指定时间筛选（今天/本周/本月）时，无日期待办不纳入结果；不指定时间时显示全部。

### 6. 智能提醒播报（v2.7.0）

触发提醒时通过 LLM 生成温暖、个性化的播报文案（≤20字），失败降级为通用文案。

### 7. 后台提醒守护

模块加载时自动启动 daemon 线程，每 30 秒检查到期事件和待办，到期则通过 `嘴巴.py` 语音播报。

### 8. 模糊时间解析（v3.9.26-27）

```
"一会儿提醒我"  → 默认 5 分钟后（"一会儿/待会儿/过会儿/等会儿/稍后"）
"等一会儿提醒我去买牛奶" → 5 分钟后
```

> 无明确数字时间时，模糊时间词默认解析为 **5 分钟后**。
> v3.9.27 强化：路由层即使误判 time_offset=1，只要原文含模糊时间词就强制为 5 分钟；
> 且 3b 路由输出注入 `raw_text`，保证降级解析能拿到原始输入。

## 数据文件

| 文件 | 格式 | 说明 |
|------|------|------|
| `todos.json` | JSON 数组 | 待办事项（15 字段标准格式，v3.9.25） |
| `events.json` | JSON 数组 | 日程事件（15 字段标准格式，v3.9.25） |

## 存储标准化（v3.9.25）

事件与待办统一使用 **15 字段标准格式**（与财务模块 v3.9.24 对齐）：

| 字段 | 说明 |
|------|------|
| `id` | 唯一标识，`schedule_event_` / `schedule_todo_` + 日期时间 + 6 位随机 |
| `type` | `event` / `todo` |
| `date` | `YYYY-MM-DD` |
| `time` | `HH:MM`（无时间保留空串） |
| `datetime` | `YYYY-MM-DDTHH:MM:00` |
| `period` | 时段标签：凌晨/早上/上午/中午/下午/晚上/深夜 |
| `title` | 标题 |
| `content` | 自动生成摘要：事件 `{period}{title}`，待办 `{period}需要{title}` |
| `detail` | 明细（预留，写入时为 null） |
| `status` | `pending` / `done`（待办专属，事件为 `pending`） |
| `location` | 地点（仅事件） |
| `repeat` | 重复规则：none/daily/weekly/monthly（仅事件） |
| `due_date` / `due_time` / `completed` | 待办兼容字段（保留旧字段以便过渡） |
| `notified` | 是否已提醒 |
| `created_at` / `updated_at` | 创建/更新时间 |

**排序规则**：始终按 `date` 降序（最新在前）+ 同日 `time` 升序（`_sort_records`），读取和保存时自动应用。

**自动迁移**：加载时自动检测旧格式（无 `schedule_` 前缀 ID 或缺 `datetime`/`content`），调用 `_migrate_schedule_to_standard_format` 补全字段并回写，不丢失任何数据。

**操作方式**：删除/完成支持按字符串 ID 或数字序号（如"删除待办1"对应列表中的第 1 项）。

## 配置

`模型.json` 中的 `use_smart_reminder` 开关（默认 true）控制智能播报文案。
