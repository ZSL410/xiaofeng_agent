# 记忆系统

> 当前版本：**v3.12.0**（情绪检测 + 记忆关联）

## 概述

晓风的记忆系统分五层：短期记忆、事实库、习惯库、会话摘要、衰减归档。

```
用户输入 → LLM 语义提取 → Python 校验 → 分类写入
                                        ↓
                              衰减调度 → 置信度动态调整 → 归档
                                        ↓
                              分层注入 Prompt → 主动预判
```

## 文件架构

| 文件 | 用途 | 格式 |
|------|------|------|
| `memory.json` | **统一记忆库（v3.9.29，15 字段标准）** | JSON |
| `对话归档.json` | **全量对话归档（v3.10.0：原文 + 摘要 + 标签）** | JSON |
| `短期记忆.json` | 最近 20 轮对话历史（L0，保持不变） | JSON 数组 |
| `facts.json` | 用户静态事实（偏好/身份/技能） | JSON |
| `patterns.json` | 动态行为习惯（含置信度） | JSON |
| `patterns_archive.json` | 过期已归档习惯 | JSON |
| `context_summary.txt` | LLM 生成的对话摘要 | 纯文本 |
| `memory_events.log` | 记忆事件日志 | 日志 |

## 统一记忆库（memory.json，v3.9.29）

`memory.json` 为统一记忆存储，采用 **15 字段标准格式**（与财务/日程模块对齐）：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `id` | string | ✅ | `memory_YYYYMMDD_HHMM_随机码` |
| `type` | string | ✅ | 固定 `"memory"` |
| `subtype` | string | ✅ | `event` / `fact` / `habit` / `reflection` |
| `date` | string | ✅ | `YYYY-MM-DD` |
| `time` | string | ✅ | `HH:MM`（未指定默认 12:00） |
| `datetime` | string | ✅ | 完整时间戳 |
| `period` | string | ✅ | 凌晨/早上/上午/中午/下午/晚上/深夜 |
| `title` | string | ✅ | 一句话摘要 |
| `content` | string | ✅ | 核心描述（默认 `{period}{title}`） |
| `detail` | string | ✅ | 完整上下文 |
| `mood` | string | ❌ | 情绪/状态标签 |
| `tags` | array | ❌ | 关键词标签 |
| `importance` | integer | ❌ | 1-10 |
| `created_at` | string | ✅ | 创建时间 |
| `updated_at` | string | ❌ | 更新时间 |

**subtype 说明**：

| subtype | 描述 | 示例 |
|---------|------|------|
| `event` | 具体发生的事情 | "今天下午和同事讨论了项目进度" |
| `fact` | 事实性信息 | "用户喜欢喝冰美式咖啡" |
| `habit` | 行为习惯模式 | "每天早上8:00泡咖啡" |
| `reflection` | 反思/感悟 | "今天发现代码重构后性能提升了" |

**主要接口**：
- `add_memory_event(title, detail, mood, tags, importance, subtype)` — 创建丰富记忆条目
- `load_memories()` — 加载（自动迁移 + 自动排序）
- `get_memories(subtype, time_filter, period, limit)` — 按 subtype/时间范围/时段查询

**工具集成**：记账、添加日程/待办后自动写入 memory.json（title="记账"/"添加日程"/"添加待办"）。

**排序规则**：date 降序 + 同日 time 升序。

**自动迁移**：首次加载时将 `facts.json`（→subtype fact）与 `patterns.json`（→subtype habit）自动迁入 memory.json，幂等不丢失数据。

## 短期记忆

- **容量**：最近 20 轮对话（user + assistant 交替）
- **生命周期**：程序退出时持久化，下次启动恢复
- **用途**：作为 LLM 对话的上下文窗口（最近 10 轮）
- **注意**：v3.10.0 起对话**原文**同步写入 `对话归档.json`，短期记忆仍只保留最近 20 轮

## 对话归档（v3.10.0，记忆系统 Phase 1）

持久化保存**每一轮对话的原文 + 摘要**，支持"回忆之前聊了什么"。与短期记忆（L0 快速通道）互补：短期记忆只留最近 20 轮，对话归档全量保留、按时间检索。

### 记录结构

| 字段 | 说明 |
|------|------|
| `id` | `dialogue_YYYYMMDD_HHMM_随机码` |
| `dialogue_id` | 会话 ID `session_YYYYMMDD_HHMM_xxx`，同一会话共享 |
| `role` | `user` / `assistant` |
| `original_text` | 原始对话文本（完整保留） |
| `summary` | 1-2 句摘要 |
| `tags` | 关键词标签 |
| `timestamp` | 完整时间戳 |
| `mood` | 情绪标签（v3.12.0 起用户轮自动检测） |
| `related_memory_ids` | 关联记忆 ID（预留，指向 memory.json，Phase 6 起可用） |
| `created_at` | 创建时间（排序依据，最新在前） |

### 主要接口

- `add_dialogue_record(role, original_text, summary, tags, mood, related_memory_ids)` — 追加记录
- `get_dialogue_summary(limit=3)` — 最近 N 轮摘要（Phase 2 prompt 注入用）
- `expand_dialogue(record_id)` — 按 ID 返回完整原文（Phase 2 按需展开用）
- `search_dialogue(keyword, limit=5)` — 按关键词搜原文/摘要/标签

### 摘要策略（三级）

| 场景 | 方式 |
|------|------|
| 工具轮（记账/日程/记忆） | 规则摘要（`记账：饭25元` / `添加日程：…` / `记忆：…`），零 LLM |
| 纯对话轮 | 3b 轻量摘要（短提示词，2s 超时） |
| 3b 失败 | 原文截断（前 20 字） |

### 主循环接入

- 工具轮经 `_record_tool_operation` 自动归档（`is_tool_round=True`）
- 纯对话轮（3b/7b/recall）显式归档（`is_tool_round=False`）
- 归档失败不阻塞对话

## 渐进披露上下文注入（v3.10.2，记忆系统 Phase 2）

**问题**：上下文窗口有限（8k-16k），全量注入记忆（≤2000 tokens）挤占对话空间。

**策略**：上下文只注入摘要，完整内容用户追问时才展开。

### 注入内容（`build_lightweight_context`）

```
当前用户：霖

最近对话摘要：
1. [user] 记账：饭25元
2. [assistant] 确认：已记录
3. [user] 添加日程：会议明天下午3点

最近操作：
1. 记账：饭25元
2. 添加日程：会议

--- 以下为详细对话历史（用户追问细节时才展开）---
如需了解某条记录的完整内容，请使用 expand_dialogue(record_id) 工具。
```

只注入三部分：**用户名 + 最近 3 轮对话摘要 + 最近 3 条工具操作**。实测约 133 tokens，对比旧全量注入上限 2000 tokens，**省约 93%**。

### 相关接口

| 函数 | 说明 |
|------|------|
| `get_context_summaries(limit=3)` | 最近 N 轮对话摘要（来自对话归档） |
| `get_recent_tool_ops(limit=3)` | 最近 N 条工具操作摘要 |
| `get_user_name()` | 检索用户名（"我叫XX"） |
| `expand_dialogue(record_id)` | 按 ID 返回完整原文（预路由 H 触发） |

### 按需展开（预路由 H）

用户问"详细说说刚才那件事"/"展开讲讲"时，确定性预路由调用 `expand_dialogue`：

- 泛化引用 → 展开最近一条对话原文
- 含关键词 → 先 `search_dialogue` 定位再展开
- 带日程/财务/查询词 → 排除，不劫持

### recall 数据源

"我刚才说了什么"优先从**对话归档**取最近 8 条摘要（可回顾 20 轮之外），归档为空才回退短期记忆。

## 标签生成与时间索引（v3.10.7，记忆系统 Phase 3）

### 标签自动生成

`记忆引擎._extract_tags(text, extra_text)` 在写入时自动为**对话归档**和**记忆库**记录生成标签：

- **实体标签**（优先）：咖啡 / 会议 / 吃饭 / 饮品 / 运动 / 娱乐 / 阅读 / 情绪 / 购物 / 喝水
- **类型标签**：财务 / 日程 / 记忆（按关键词判定），无命中兜底「聊天」
- 去重、上限 5 个；`add_dialogue_record` / `add_memory_event` / `_fact_to_memory` 均集成
- `backfill_tags()` 启动时补齐历史空标签（幂等，只补空不改已有）

### 搜索接口

| 函数 | 说明 |
|------|------|
| `search_by_tags(tags, limit)` | 按标签搜记忆库（单标签或列表，子串匹配） |
| `search_by_time(date_range, period, limit)` | 按时间范围 + 时段搜记忆；时间词支持 今天/昨天/本周/上周/本月/**周一~周日**/**上周X**/YYYY-MM-DD/(start,end) |
| `search_by_keyword(keyword, limit)` | 搜**记忆 + 对话归档**（content/title/detail/original_text/summary/tags），统一结构返回；v3.10.9 起跳过"工具操作：/确认：🔍"搜索自噪音记录，避免搜索结果被搜索动作本身污染 |

### 路由集成

- **预路由 (C) 搜索**："搜索咖啡" → `search_by_keyword`（记忆 + 对话归档）
- **预路由 (D) 记忆查询**："查看今天的记忆" → `search_by_time`
- **预路由 (I) 时间回查**："上周三发生了什么" → `search_by_time("上周三")`
- **3b 路由**：`search` / `query+memory` 意图同样走上述接口

## 置信度衰减与记忆整合（v3.10.8，记忆系统 Phase 4）

每条记忆带有生命周期字段（v3.10.11 起**创建即补齐**，旧记录启动时自动补齐，幂等）：

| 字段 | 缺省 | 说明 |
|------|------|------|
| `tier` | `L1` | 记忆层级：L1 情景 / L2 语义长期 |
| `confidence` | `importance/10` | 置信度 0~1 |
| `last_retrieved` | `created_at` 日期 | 最近检索日 |
| `retrieved_count` | `0` | 检索次数 |

### 生命周期规则

- **日衰减**：每经过一天且未检索，`confidence -= 0.005`（增量式，基于 `last_decay_run`，避免重复扣减）
- **L1→L2 提升**：`confidence ≥ 0.8`，或 **同一实体主题标签出现 ≥ 3 次** → `tier="L2"`（置信度保底 0.8）
- **检索提升**：`record_retrieval()` 每次 `confidence +0.05`（封顶 1.0）、`retrieved_count +1`
- **归档**：`confidence < 0.2` 或 **90 天未检索** → 移入 `archive/memory_archive.json`

### 接口

| 函数 | 说明 |
|------|------|
| `run_consolidation()` | 日衰减 + L1→L2 提升（每日执行） |
| `run_archive()` | 归档低置信度/过期记忆 |
| `decay_confidence(id, delta)` | 单条记忆置信度调整（手动 / 默认日衰减） |
| `promote_to_l2(id)` | 手动提升单条记忆到 L2 |
| `record_retrieval(id)` | 检索提升（脑.py 展示结果时自动调用） |
| `_maybe_run_daily_maintenance()` | 启动时每日维护（按日期幂等） |

## 对比分析（v3.11.0，记忆系统 Phase 5）

让晓风**读懂数据**——跨期对比、统计洞察，回答"趋势"而不只是"记录"。

### 支持的功能

| # | 功能 | 示例问法 | 输出样例 |
|---|------|----------|----------|
| 1 | 周对比 | 本周花了多少？比上周多吗？ | 本周共花费213元，上周共花费95元，比上周多124% |
| 2 | 月对比 | 本月开销比上个月大吗？ | 本月共花费373元，上月共花费339元，比上月多10% |
| 3 | 分类对比/汇总 | 这个月吃饭花了多少？比上个月呢？ | 本月餐饮支出166元，上月餐饮支出166元，与上月持平 |
| 4 | 最大开支 | 这个月最大的开支是什么？ | 最大开支：日常消费 30元 (2026-08-12) |
| 5 | 高频活动 | 我最近经常做什么？ | 1. 喝咖啡 (26次)、2. 吃饭 (16次)… |
| 6 | 消费时段 | 我一般什么时候花钱最多？ | 凌晨 (56%)、深夜 (36%)、上午 (5%) |
| 7 | 周总结 | 这周我做了什么？ | 本周总结：共花费213元，主要支出在生活(143元)、餐饮(41元)，共9项日程，完成6次会议… |

无数据时统一友好提示：**「这段时间还没有数据记录哦」**。

### 数据源（跨模块只读）

- 财务：`01_工具模块/财务模块/local_archive.json`（支出 type=expense）
- 日程：`01_工具模块/日程模块/events.json` / `todos.json`
- 记忆：`memory.json`（实体标签）+ `对话归档.json`（用户轮标签）

### 主要接口

| 函数 | 说明 |
|------|------|
| `run_analysis(user_input)` | **统一入口**：关键词 → 具体分析函数 → 自然语言回复；非分析输入返回 `None` |
| `compare_week_over_week()` | 本周 vs 上周支出（金额/差额/百分比） |
| `compare_month_over_month()` | 本月 vs 上月支出 |
| `get_category_summary(period)` | 按分类统计支出（复用 Phase 3 `_resolve_date_range`） |
| `compare_category_across_periods(cat, base, compare)` | 单分类跨期对比 |
| `get_highest_expense(period)` | 时段内最大单笔开支 |
| `get_frequent_activities(limit)` | 高频活动（记忆实体标签 + 财务来源 + 对话归档三源合并） |
| `get_spending_pattern(period)` | 消费时段分布（凌晨→深夜 7 时段 + 百分比） |
| `generate_weekly_summary()` | 本周综合总结（财务 + 日程 + 记忆活动） |

### 路由集成

脑.py 新增「分析」意图，**四级保障**：

1. **确定性预路由**（最高优先）：`_ANALYSIS_RE` 分析信号词 + `_ANALYSIS_EXCL_RE` 排除词（记住/添加/删除/搜索/提醒…）→ `run_analysis`
2. **3b 路由**：`_ROUTE_PROMPT_3B` 新增 `analyze` 意图，含"分析优先级"规则（分析词优先于财务词）
3. **7b 路由**：`_ROUTE_PROMPT_V2` 新增「### 对比分析(analyze)」工具说明 + 主分发 `elif tool == "分析"`
4. **降级关键词匹配**：分析关键词分支（置于财务之前，因"比上周"的分析查询也含"花了"）

### 关键设计

- **消费语境门控**：类别分析必须伴随消费词（"我喜欢喝拿铁"不触发分析）
- **强意图排除**：记忆记录/日程添加/删除等内置排除（防劫持）
- **显示名合并**：高频活动按显示名去重合并（"饭"+"吃饭" → "吃饭"）

## 情绪检测与记忆关联（v3.12.0，记忆系统 Phase 6）

让晓风**懂心情**、**懂联系**——记录情绪标签 + 建立记忆之间的关联网络。

### 情绪检测（hybrid）

| 层 | 触发条件 | 行为 |
|----|----------|------|
| 关键词 | 命中情绪关键词表（开心/焦虑/累/不懂…，9 类） | 直接返回该情绪（零 LLM） |
| LLM 兜底 | 无关键词 + 文本含情绪信号词 + 已注入 LLM 钩子 | 3b 分类（2s 超时） |
| 无结果 | 均未命中 | 返回 `None`（不写入 mood） |

9 类情绪：**开心 / 难过 / 生气 / 焦虑 / 平静 / 兴奋 / 疲惫 / 专注 / 困惑**。

自动写入位置：
- `add_dialogue_record`（role=user）→ `对话归档.json` 的 `mood`
- `add_memory_event` → `memory.json` 的 `mood`

`set_mood_llm_fn(fn)` 模块级 LLM 钩子由脑.py 启动时注入 `_call_ollama_3b`；未设置则纯关键词检测（引擎可独立运行，不拖慢主循环）。

### 记忆关联（知识图谱）

| 关联维度 | 判定 |
|----------|------|
| 同实体 | 实体主题标签重叠 ≥1（咖啡/会议/吃饭/运动…） |
| 同标签 | 标签重叠 ≥2 |
| 时间临近 | datetime 相差 ≤1 小时 |

| 强度 | 值 | 判定 |
|------|----|------|
| 强 | 1.0 | 同实体 + 同标签 + 时间临近 |
| 中 | 0.7 | 同实体（部分条件） |
| 弱 | 0.4 | 仅同标签 ≥2 或仅时间临近 |

`related_ids` 存储（additive，不覆盖已有；同对 strength 取 max、reasons 合并去重）：

```json
[{"id": "memory_x", "strength": 0.7, "reasons": ["同实体:咖啡"], "linked_at": "2026-08-16T01:05:00"}]
```

触发时机：
- `add_memory_event` 创建后自动 `find_related_memories` → `link_memories`（双向）
- 每日维护 `_maybe_run_daily_maintenance` 追加 `build_association_network` 补全历史关联

### 接口

| 函数 | 说明 |
|------|------|
| `detect_mood(text, llm_fn=None)` | 情绪检测（返回 9 类之一或 None） |
| `set_mood_llm_fn(fn)` | 注入情绪检测 LLM 钩子 |
| `find_related_memories(new_memory, limit)` | 查找相关记忆（返回 id+strength+reasons） |
| `link_memories(memory_id, related)` | additive 双向写入 related_ids |
| `build_association_network(limit_per)` | 批量重建全库关联网络（幂等） |
| `get_related_memories(memory_id, limit)` | 查询某记忆的关联记忆（按强度降序） |

### 对话集成

- 预路由 **(J) 关联记忆查询**："咖啡和什么相关" / "查看关联记忆" → 提取主题 → 定位记忆 → 展示关联记忆
  （排除 添加/记住/删除/提醒/记账 等强意图，防劫持）

## 事实记忆（facts.json）

存储用户直接陈述的事实性信息。

### 字段说明

| 字段 | 说明 |
|------|------|
| `id` | 唯一标识 `fact_001` |
| `content` | 事实内容 |
| `category` | 分类：偏好 / 身份 / 技能 / 习惯 / 其他 |
| `source` | 来源：对话 / 提炼 / 用户确认 |
| `pinned` | 是否固定注入 Prompt |
| `importance` | 重要性 0~1 |
| `embedding` | 向量预留（未来语义检索） |

### 写入方式

1. **LLM 自动提取**：对话中检测到重要信息时自动提取（v3.7.0 新增）
2. **手动添加**：通过 `记忆引擎.add_fact()` 编程接口

## 习惯记忆（patterns.json）

存储从历史行为中提炼的习惯规律。

### 字段说明

| 字段 | 说明 |
|------|------|
| `id` | 唯一标识 `pattern_001` |
| `content` | 习惯描述 |
| `type` | 类型：time_based / interval / association |
| `frequency` | 触发频次 |
| `confidence` | 置信度 0~1（动态调整） |
| `last_trigger` | 最近触发时间 |
| `rejected` | 用户是否明确拒绝 |
| `archived` | 是否已归档 |
| `related_to` | 关联记忆 ID（未来图谱） |
| `relation_types` | 关系类型（未来图谱） |

### 习惯类型

| 类型 | 发现什么 | 示例 |
|------|----------|------|
| `time_based` | 同一内容在相似时段重复 | 每天 8:00-9:00 泡咖啡 |
| `interval` | 同一内容以固定间隔创建 | 每 30 分钟休息 |
| `association` | A 创建后频繁跟随 B | "冥想"后常跟"休息" |

## 数据提炼（v3.3.0）

`数据提炼.py` — 扫描历史待办/日程，自动发现三种行为模式。启动时每日自动提炼一次。

## 衰减与遗忘机制（v3.7.0 增强）

### 衰减调度

`衰减调度.py` 作为独立模块运行，每日检查一次：

| 条件 | 操作 |
|------|------|
| `last_trigger > 30天` | `confidence *= 0.95` |
| `confidence < 0.3` 且 `last_trigger > 60天` | 标记 `archived: true`，移至归档 |
| `rejected = true` | 不衰减，但置信度过低时归档 |

### 手动操作

| 函数 | 效果 |
|------|------|
| `decay_patterns()` | 执行衰减（兼容 v3.6.0） |
| `reject_pattern()` | 用户拒绝 → confidence -0.30 |
| `boost_pattern()` | 用户确认 → confidence +0.10（⚠️ 已定义但当前未在脑.py 接线） |
| `run_decay()` | 新版衰减接口（v3.7.0） |
| `archive_expired()` | 归档过期条目 |
| `manual_cleanup()` | 完整整理（衰减+归档+去重） |

## Prompt 注入策略

### 分层注入

| 层级 | 内容 | 上限 | 触发条件 |
|------|------|------|----------|
| 必注入 | context_summary + pinned facts | 5 条事实 | 始终 |
| 按需注入 | 高置信度 patterns（confidence > 0.5） | 5 条 | 涉及日程/提醒关键词 |
| Token 控制 | 所有注入内容 | 2000 tokens | 超限按 importance 截断 |

### 注入格式

```
[用户记忆]
- (事实) 用户喜欢喝冰美式咖啡
- (事实) 用户是AI开发学习者

[近期摘要]
用户正在构建个人智能体"晓风"。偏好简短回答。

[行为习惯]
- 每天上午8:00-9:00 泡咖啡 (置信度:85%)
```
