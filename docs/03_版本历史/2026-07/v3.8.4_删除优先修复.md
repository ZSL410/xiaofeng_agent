# v3.8.4 — 删除关键词无条件优先规则

**日期**：2026-07-22  
**类型**：修复 (fix) — 路由误判  
**影响范围**：`00_核心主体/脑.py` — `_ROUTE_PROMPT_V2`

## 变更动机

测试发现两个路由误判案例：

| 用户输入 | 实际行为 | 问题 |
|----------|----------|------|
| "删除今天的财务数据" | → 财务 query | LLM 看到"财务"优先匹配了查询/记账，忽略了"删除" |
| "把今天这笔的金额删除" | → 财务 record | "金额"+"删除"→ LLM 倾向于记账而非删除 |

根因：虽然 v3.8.3 已有"删除优先于一切"规则，但它被放在"优先级规则"第2条，LLM 可能在看到"财务"关键词时已经形成了判断倾向。需要将删除规则提升到 prompt 最顶部，使其成为 LLM 处理输入时首先看到的规则。

## 变更内容

### 新增 `🚨 删除关键词优先规则`（prompt 最顶部）

在 `_ROUTE_PROMPT_V2` 的第3行（紧跟"当前时间"后），插入**最高优先级**规则块：

```
## 🚨 删除关键词优先规则（最高优先级，覆盖所有其他意图）

一旦用户输入中包含 "删除"/"删掉"/"清空"/"清除"/"去掉" 中的任意一个，
该输入的意图必须判定为删除相关，不再判断财务/日程/聊天等其他意图。

即使同时出现 "财务"/"日程"/"记账"/"查看"/"花了"/"多少" 等其他关键词，
删除关键词的优先级高于一切。
```

**关键设计**：
- 放在 prompt 最顶部（在否定词规则之前），确保 LLM 第一眼就看到
- 使用 `🚨` emoji 增强视觉显著性
- 提供具体的误判案例作为反例，让 LLM 学习"即使有 X 关键词，只要含删除就走删除"
- "禁止路由到财务"等强硬措辞

### 决策链调整

```
旧:
1. 否定词检查
2. 删除检查
3. 财务/日程/聊天

新（v3.8.4）:
1. 🚨 删除关键词检查（无条件优先）
   → 含删除+无否定 → 直接走删除流程，禁止路由到财务
   → 含删除+有否定 → 排除删除，继续
2. 其他否定词检查
3. 财务/日程/聊天（只有不含删除时才进入）
```

### 与否定词规则的交互

否定词规则在删除规则之后，处理的是"删除被否定"的例外情况：
- "删除今天的财务数据" → 无否定 → 🚨规则生效 → 删除 ✅
- "不要删除数据" → 有否定 → 删除规则不生效 → 进入其他判断 ✅
