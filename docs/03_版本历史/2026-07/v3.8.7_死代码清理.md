### L4 — 低置信度拦截扩展到财务和删除

**之前**：仅 `add_reminder` 在 `confidence < 0.6` 时触发确认门控。财务操作和删除操作即使置信度极低也直接执行。

**之后**：`confidence < 0.6` 的财务/删除操作被拦截并提示用户重新表述：

```python
if confidence < 0.6:
    if tool == "日程" and action == "add_reminder" and intent.get("params"):
        # 已有逻辑：显示提醒描述，等待确认
        ...
    if tool == "财务":
        # 新增：拦截并提示
        print("🤔 不太确定你的意思，请再说清楚一点...")
        continue
    if tool == "日程" and action in ("delete_reminder", "manage"):
        # 新增：拦截并提示
        print("🤔 不太确定你的意思，请再说清楚一点")
        continue
```

设计选择：低置信度下的财务/删除操作不进入 `_pending_confirmation` 状态机（该机制仅支持提醒确认），也不进入 `_pending_clarification`（该机制专用于删除范围澄清）。而是直接提示用户重新表述，避免误操作。下一轮对话中用户重新表述后可获得更高的路由置信度。
