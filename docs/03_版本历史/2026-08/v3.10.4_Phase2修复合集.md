# v3.10.4 — Phase 2 修复合集

> **日期**：2026-08-12 ｜ **类型**：🐛 修复合集（Phase 2 实测暴露 4 项）

## 背景

Phase 2 渐进披露实测暴露 4 个问题：消费金额误判记忆、展开触发覆盖不足、展开返回摘要、提醒内容截断。

## 变更内容

### 1. (F) 预路由：消费带金额 → 确定性财务记账

**问题**："晚上买了根雪糕花两块钱挺好吃的"被 3b 误判为 memory（创建 fact_003），财务未记账。

**修复**：(F) 预路由改为双分支确定性判定：

| 输入特征 | 路由 |
|----------|------|
| `买了/消费/花了/支付/用了` + **有金额** | **财务记账**（`call_tool("财务")`，绕过 3b） |
| `买了/消费/花了` + 无金额 | chat（购物陈述） |

排除词补充疑问标记（`吗/呢/？/?`），防止"花了100元吗"被误记为支出。

**验证**：财务模块正确解析 `晚上买了根雪糕花两块钱挺好吃的` → **amount=2**，source=日常消费。

### 2. (H) 展开触发增强：详细地 / 跟我详细 变体

**问题**："详细地跟我说一说"被 3b 判为 clarify。

**修复**：`_EXPAND_RE` 新增模式：

- `详细地 + 说/讲讲/一说/说说`（详细地说一说）
- `详细地 + 跟我/和我说/跟我说 + 说/一说`（详细地跟我说一说）
- `跟 + 我 + …详细`（跟我详细说说 / 跟我说一下详细）

关键词清洗补充 `跟/一说/说一下`。

### 3. (H) 展开返回 original_text（非 summary）

**问题**：展开返回摘要式内容（如"用户确认了昨晚的记账内容…"）。

**排查结论**：`expand_dialogue()` 本就返回完整记录（含 `original_text`），归档也正确分字段存储。问题在展开的**目标记录选择**——泛化引用时命中了助手的工具/摘要回复。

**修复**：泛化展开**优先最近一条 user 记录**（用户的原话），无 user 记录才回退最近一条；展示用 `original_text`，缺失时给占位而非回落 summary。

### 4. 提醒内容不截断

**问题**："明天中午十二点半记得叫我有个小测试"标题被截断/日期词漏入（旧结果为"明天有个小测试"，"明天"不应在标题）。

**修复**：

- `_clean_title` 噪声词补充日期词（明天/今天/昨天/后天/周X/下周 等），避免"明天"漏进标题
- `_add_todo` 新增 `detail` 参数保存**完整用户原始文本**，提醒/待办创建时写入
- 无截断上限（标题可至任意长度），长提醒完整保留

**验证**：`明天中午十二点半记得叫我有个小测试` → 标题`有个小测试`（含"小测试"、无日期噪声），detail 保存完整原文；`明天下午三点记得叫我下午要去机场接客户张经理顺便买杯咖啡` → 标题 16 字完整保留。
