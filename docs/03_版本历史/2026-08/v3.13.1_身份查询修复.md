# v3.13.1 — 身份查询修复

> **日期**：2026-08-16 ｜ **类型**：🐛 修复 —— "我是谁"查不到用户名字

## 背景

Phase 1（基础对话）测试：用户先说「记住我叫霖」（系统确认已记住），随后问「我是谁」/「我叫什么」，
系统却回答 *"我还不太确定你的名字，你可以告诉我，比如'记住我叫XX'"*。

## 根因分析

数据核查确认**写入侧正常**：

- `facts.json` 存在 `我叫霖` 事实（`add_fact` 写入，Hook A "记住X" 触发）
- `memory.json` 存在对应记录：`subtype="fact"`、`content="我叫霖"`、日期 **2026-08-08**
- `get_user_name()`（记忆引擎，全量检索）实测返回 `'霖'` ✅

问题出在**读取侧**的预路由 (B) 身份查询（`脑.py`）：

- 旧实现**没有调用** `get_user_name()`，而是在函数内重写了一份内联检索，
  用的是 `get_memories(limit=50)` —— 只取按日期排序的最新 50 条。
- 而名字事实通常很早就写入（本例 rank **#52 / 59**，08-08 早于大量 08-12~08-16 记录），
  落在 top-50 窗口之外 → `name=None` → 走兜底文案。

这是**潜伏 bug**：只要记忆库超过 50 条且名字事实早于最近 50 条，身份查询必然失败，
与用户何时、以何种方式记住名字无关。

## 修复内容

### `脑.py` — 预路由 (B) 身份查询

- 删除内联的 `get_memories(limit=50)` 检索循环（含函数内 `from 记忆.记忆引擎 import get_memories`）。
- 改为直接调用模块顶层已导入的 `get_user_name()`（全量检索，不受 limit 截断）。
- 保留 `patterns.json` 兜底检索（老数据兼容，逻辑不变）。
- 触发正则、回复文案、`_record_tool_operation` 均不变。
