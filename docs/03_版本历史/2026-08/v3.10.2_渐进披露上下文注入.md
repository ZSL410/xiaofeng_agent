# v3.10.2 — 渐进披露上下文注入（记忆系统 Phase 2）

> **日期**：2026-08-12 ｜ **类型**：⚡ 上下文注入策略重构（省约 80% 上下文）

## 背景

v3.10.1 的上下文注入采用"全量注入"：每次对话把 `context_summary + pinned facts + 高置信度 patterns` 全部塞进 system prompt（上限 2000 tokens）。在 8k-16k 上下文窗口下，这会挤占大量实际对话空间，且大量记忆内容用不上。

**目标**：改为"摘要先行 + 按需展开"——上下文只注入摘要，完整内容由用户追问时才通过 `expand_dialogue()` 展开。

## 变更内容

### 1. 新增接口（`记忆引擎.py`）

| 函数 | 说明 |
|------|------|
| `get_context_summaries(limit=3)` | 最近 N 轮对话摘要 `[{id, role, summary, timestamp}]`（来自 `对话归档.json`） |
| `get_recent_tool_ops(limit=3)` | 最近 N 条工具操作摘要 `[{id, summary, timestamp}]`（role=user 且 summary 以 记账：/添加日程：/记忆：/日程：/工具操作： 开头） |
| `get_user_name()` | 从记忆库检索用户名（"我叫XX"等），供上下文注入 |

### 2. 轻量上下文构建（`脑.py` `build_lightweight_context`）

只注入三部分，其余一律不注入：

```
当前用户：霖

最近对话摘要：
1. [user] 记账：饭25元
2. [assistant] 确认：已记录
3. [user] 添加日程：会议明天下午3点

最近操作：
1. 记账：饭25元
2. 添加日程：会议

--- 以下为详细对话历史（用户追问细节时才展开）---
如需了解某条记录的完整内容，请使用 expand_dialogue(record_id) 工具。
```

- `chat_with_xiaofeng` 改用 `build_lightweight_context`（不再调用全量 `build_injection_context`）
- 实测：轻量上下文约 **133 tokens**，对比旧全量注入上限 **2000 tokens**，缩减约 **93%**

### 3. 按需展开（`脑.py` 主循环预路由 H）

新增确定性预路由 **(H) 展开请求** → `expand_dialogue()`：

| 用户输入 | 处理 |
|----------|------|
| "详细说说刚才那件事" / "展开讲讲" | 泛化引用 → 展开最近一条对话原文 |
| "展开咖啡的事" | 提取关键词 → `search_dialogue(keyword)` 定位 → 展开 |
| 带日程/财务/查询词 | 排除，不劫持 |

返回格式：`📖 你说：\n「完整原文」\n（时间戳）`。

### 4. recall 改用对话归档

`recall` 意图（"我刚才说了什么"/"刚才干了什么"）数据源从**仅短期记忆 12 轮**改为**优先对话归档最近 8 条摘要**（可回顾 20 轮之外），归档为空才回退短期记忆。

### 5. Bug 修复：用户名提取

`get_user_name()`（及脑.py 身份预路由 B）原将 content+title 拼接成"我叫霖我叫霖"，贪婪正则捕获出"霖我叫霖"。已改为 **content 与 title 分开匹配**，正确返回"霖"。

## 行为变化

| 场景 | 之前 (v3.10.1) | 之后 (v3.10.2) |
|------|----------------|-----------------|
| 普通对话 | 注入全部记忆内容（≤2000 tokens） | 只注入 3 摘要 + 3 操作 + 用户名 |
| 我刚才说了什么 | 仅短期记忆 12 轮 | 从对话归档取最近 8 条摘要 |
| 详细说说刚才那件事 | 不支持 | 调用 expand_dialogue() 展开原文 |
| 用户名显示 | "你叫霖我叫霖呀"（错误） | "霖"（正确） |

## 自检结果

| # | 测试 | 结果 |
|---|------|------|
| 1 | 新会话上下文只含 用户名+3摘要+3操作，无全量记忆 | ✅ |
| 2 | "我刚才说了什么" → 从对话归档检索 | ✅ |
| 3 | "详细说说刚才那件事" → 调用 expand_dialogue() 返回原文 | ✅ |
| 4 | 上下文 133 tokens vs 旧上限 2000 tokens，缩减 93% | ✅ |

> 自检 **4/4 + 主循环端到端**（展开/recall/对话注入）通过。`build_injection_context` 等旧函数保留未删（Phase 2 为增量修改）。

## 限制与后续

- 展开目标选择为启发式（最近一条 / 关键词搜索）；"那件事"的精确指代消解留待后续
- Phase 3 将完善标签生成 + 时间索引（"搜索咖啡"/"第一天发生了什么"）
